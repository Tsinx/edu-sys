# 港口长期独立经营：管理、教学与本机使用

本系统以虚构的东湾港为教学情境。学生独立管理一个港口，采用“制定规则—经营一段时间—阅读反馈—调整决策”的循环。常规业务按规则自动执行，重大事件由本人批准目标与预算。计算在浏览器工作线程中进行，关闭页面后不继续消耗经营时间。

## 学生本机启动

当前分发包：`output/port-enterprise-guided-semester-student-windows-x64-2026-10-28.zip`。完整解压后双击 `Start-PortEnterprise.cmd`。包内含 Windows x64 Node 运行文件，学生无需安装 Node、数据库、求解器或AI服务。建议使用近期 Edge 或 Chrome。

启动器仅在 `127.0.0.1` 提供程序文件，默认尝试8217端口，重复启动复用同一目录的服务。自动存档属于当前浏览器和地址；跨电脑、更换浏览器、清理浏览器数据或更换端口前应导出JSON。停止程序只停止本包的文件服务，保留浏览器存档。

支持1、3、5年经营期，包含接管、增长、绿色、韧性四类情境。教学练习与正式场次分别保存。旧课堂六类分段实验沿用原入口与原规则。

## 多窗口与故障恢复

每个标签页分别记住正在经营的场次。刷新本页会恢复自己的港口；另一个窗口保存其他练习，不会让本页切换场次。同一场次出现较新进度时，本窗口暂停写入，可以恢复较新记录、另存为独立个人练习，或先导出本窗口的经营记录。较新记录不会被过期窗口覆盖。

业务计算每次只接受一个操作，同一决定的快速重复点击也不会再次执行；正常的连续经营按既定时步推进。回放重建失败不切换现场状态，只读预览不写回经营进度，导出完整经营记录仍导出实际场次。

计算线程中断后，最后确认的记录保留，可恢复本机计算或导出已有记录。保存失败时显示“保存需要处理”，存档窗口和带教卡提供“重试保存进度”与经营JSON备份入口；没有完成本机写入时不能把等待保存当作正式提交前已保存。

本机数据库格式升级为2以阻止旧窗口绕过冲突检查。升级保留已有长期引擎2.0记录，不改变经营指令、规则或成绩。未刷新的旧窗口若提示无法保存，应先导出未保存的经营记录，再刷新使用当前客户端；导入另建记录，原存档保留。

## 港口场景与主要入口

主界面以港口为中心，页头保留“经营菜单”“事件”“周报与统计”。选择作业区可看等泊、库存与可用资源；逐船、逐批追踪收在“查看具体业务”中。三维中的集装箱区按真实区块规则和库存层数作示意，不能据图数出实际箱量。三维不可用时使用业务平面图。

经营菜单先显示经营方针、堆场、班表、能源、技术、客户、周报、存档和训练等入口。全部设备、工程、报价、合同、资金、监管、物流、治理、手册和正式任务功能仍保留在菜单或“全部业务与精细参数”中。搜索可直接找到精细功能。

自由经营可按小时、班次、生产日、经营周、30日或公开观察点推进。打开工作窗口、编辑输入或切换浏览器标签页时暂停连续经营。新出现的待授权重大事件中断当前推进；已批准的处置继续按时间和实际资源执行。每周报告可从事件和统计入口回看。全屏由同一底部工具栏控制，不重新创建仿真线程或场景。

## 主要管理决策

- 经营方针：稳健、履约、流转、节能四种起点模板，实际改变优先级、公路限额、补能和可用车保障参数。参数均可进一步调整。
- 堆场规划：进口、出口和共享区比例；后续入场最高2至4层；按入场顺序、预计周转ABC、航次归组；固定分区、共享缓冲或动态货位。
- 班表：三班均衡、日班加强、保留后备。模板重新分配已有人员，保留技能、培训、工资及入职历史。培训者不计可用生产人员；预备人员仍按每日8小时保留基本工资。招聘、培训与逐组排班继续开放。
- 补能与维护：低电量补能、错峰轮充、谷时优先；目标电量、可用车比例、同时主动补能上限；标准、夜间优先或提前维护。紧急低电量和危险设备不等待常规时窗。
- 异常授权：控制后修复，或针对供电/系统中断选择连续性优先。批准累计费用上限后，系统核查证据、隔离、占用技术人员并排修，技术完成后恢复。备用启动4.5万元、运行1200元/小时，技术修复启动3万元；直接事故损失另记。预算到限或现金不足会要求再次决定。

策略不会重写历史。修改堆场规则后，已有库存保留原位；减少允许堆高可能降低新入场空间，不能把名义物理容量全当作新规则下的可用容量。

## 堆场与水陆接续的真实约束

两个集装箱作业区各有10个区块，每个区块用5组并行批次堆垛表示，物理上限4层。进口、出口和共享比例按10%区块调整。ABC在本情境按预计周转分类：24小时内为A、48小时内为B，其余为C。它与按货值、数量等口径的ABC不同；分类依据与货位分配方式是两个独立决策。

固定分区只能用本方向的区块；共享规则增加共享区；动态规则允许使用全部区块。提取被上层遮挡的货物必须有真实空位完成移位，消耗场桥与必要的车辆能力，并按55元/TEU次记实际翻箱费用。内部距离影响搬运工作量。没有空位或能力就继续等待，不能仅扣钱后瞬间取走下层货物。

周转估计仅使用公开期限、当前放行信息与可复现误差，不读取隐藏的实际未来到达。信息协同投产后，估计误差范围由约±12小时缩至±4小时，同时缩短后续单证回执等待。

铁路和驳船采用接续集结与固定发运窗口：进口货物可提前由场桥、闸口移至集结区，窗口内实际发运；出口在到车/到驳后可跨小时逐步过闸。每作业区铁路窗口共享600独立货种单位，驳船500；进口集结容量分别600与500。物理库存继续守恒，已集结货物不能直接换路径。

## 技术升级如何影响管理

“技术与升级”将信息协同、自动化、电动化、流线、联运、岸电、监测和防护工程与实际约束对应：先显示投资、工期、作用及限制，再允许启动。全部建设类型和位置选择保留在完整工程页。

自动化工程提供接口，AGV和智能闸口仍需单独采购、交付与验收，并占用数字岗位、供电、电池等资源。电动化需要补能秩序；供电扩容增加共享容量和充电接口；岸电占用供电；光伏只在本模型的日间条件下发电，没有虚构夜间储能放电。维护、保安、防洪等措施通过实际维护与风险过程起作用。

这里使用本地规则调度、批次堆垛与版本化情境参数，不声称已经实现现实港口的智能优化器。动态货位、自动化或新设备均不保证所有情境下更优。

## 前半年游戏带教

从场景左侧“开始前半年带教”另建练习港口，保留当前场次。带教从2027年1月1日经营至7月1日，共181日、4344小时、28项管理任务。它使用实际业务窗口与经营指令，不需要阅读章节、回答知识题或撰写复盘才能前进。

界面每次只指出一个动作：演示鼠标移向真实控件并点击，金色边框循环高亮。学生亲自点菜单、选择字段、发布决定或查看实际成果；正确的缺省字段自动略过，但发布操作必须实际完成。提示卡避开目标，窗口自动滚动到当前字段，切换窄屏和全屏后重新定位。

1. 一月：批准稳健经营，运行首周、领取真实交付成果；配置进口、出口与共享缓冲，组合预计周转ABC和动态货位；核对首月现金与利润。
2. 二月：订购电动集卡，建设信息协同，重新安排三班与维护秩序。采购和工程保留实际支出与交付周期。
3. 三月：等待设备真实交付，找到并验收新增车辆，再为车队设置错峰轮充。
4. 四月：核对信息协同已投产，观察单证与周转信息改善；改用履约优先策略，签下实际可用的季度合同。
5. 五月：核对合同已完成的实际交付，启动流线改造，并等待45日工期。
6. 六月：验收流线成果，完成181日经营，核对第六份月报，再接管余下经营。

待授权重大异常会插入当前动作。学生按提示批准处置方案与费用上限，系统继续执行修复；之后回到原管理任务。成功反馈来自实际指令、交付、月报、验收和履约记录，失败指令不会完成任务。教学元数据不作为正式成绩。

带教期间除当前目标、鼠标重播、退出和全屏按钮外，其余经营控件不能点击或取得键盘焦点；Escape不会关闭业务窗口绕过步骤。经营指令另有同等约束，不能通过其他表单提前推进、重复采购或发布无关决定。可以退出并保存当前经营和字段草稿；结算过程中请求退出会等待已批准的这一轮完成，再保留实际时点；没有额外推进经营时间时可继续原步。自由经营已改变时间或场次已封存时，另开新的带教练习。

半年结束后解除引导锁定，同一座港口保留设备、工程、合同、资产与完整记录，继续经营至本场三年期末；自由练习仍可另建1、3、5年场次。带教完成不会封存、结束合同或免除待处理业务。结业时可导出带教足迹；完整经营JSON与月报CSV仍从存档和统计入口导出。考核场次可以另开独立练习，不改动正式任务。

## 收获反馈与试验

每168小时形成经营周报，经营期末不足一周也结算。界面保留最近60期周报，完整月报继续保留；较早周报可通过经营JSON的只读回放重建。周报分别列各货种实际交付与积压，不混合TEU、吨、立方米、辆和人。收入、运营费用与现金变化分开；运营费用不含折旧、利息和税费，应再看完整月报。

周报显示真实翻箱、每100 TEU提取的翻箱次数、用电与补能、充电等待及策略变更。受阻记录为货批的小时尝试次数，不是全港停工小时。前后周的需求、天气和事件可能不同，不能直接将差额解释为策略因果效果。

完成首周后，可在工作线程内重新运行已经观察过的第一周，只改变T1固定分区/动态货位，其他初始决策、需求、天气、设施和人员相同。结果不改变当前港口、时钟、经营指令或正式成绩。对照无改善也是有价值的结果，应继续找其他瓶颈。

九项经营足迹根据真实记录点亮，包括首份周报、堆场规划、空间调剂、六类交付、技术投产、事件恢复、年度与期末。足迹不赠送现金，也不替代课程成绩。

按本次要求，长期引擎2.0不迁移旧版长期存档。旧浏览器数据和既有分发包保留；未知或不匹配规则明确拒绝导入，不静默重算。原课堂分段实验不受此版本切换影响。

经营JSON包含情境与完整指令；导入会另建记录。只读回放从指令重建，不覆盖现场。月报CSV用于数据分析；学习报告用于过程复盘，都不能代替经营JSON。封存后可在“存档与回放”导出包含本地状态哈希与成绩的封存核验包，平台按相同版本独立重放，核对完整状态哈希及成绩。正式任务要求本人身份、固定条件、四类不少于20字的决策说明，以及主动提交后取得核验回执。文字完整性不等于文字质量已经得到自动评价。

本机数据库按记录修订号执行原子写入。多窗口发生冲突时，可以读取较新记录、保留当前练习副本或导出当前进度，不能静默覆盖。旧写入协议不能绕过此检查。读取失败不会自动另建一座港口；写入失败时仍可导出当前已确认记录，重试保存不重复执行经营动作。

正式场次领取按学生、任务和场次序号保留幂等回执。快速连点、迟到响应或窗口重新打开不会消耗同一场次的额外次数；关闭任务窗口后的迟到响应不切换当前港口。封存提交先将同一编号和封存包保存到本机，断网或回执丢失时沿用原包重试；已核验场次明确显示提交完成。规则按键和值核对，不因JSON字段顺序不同报冲突；已归档任务不能新建场次或重新开放。

多年核验和恢复按实际重放进展刷新等待计时，浏览器单次计算和服务器核验仍保留15分钟总时限；服务器另有90秒无进展检测。只读回放也报告真实重建进展。计算中断保留最后确认的记录，可恢复线程或导出备份。以上是程序资源保护，不代替经营规则、真实结果或正式回执。

教学单独使用本机进度元数据，不作为服务端可相信的成绩。离线包不代替正式平台的身份、任务领取或成绩回执。
