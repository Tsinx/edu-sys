# 校园服务器部署与验收

日期：2026-09-08。本次交付将计算移到师生端，把校园 PC 保留为网页入口、记录中心和 AI 代理。部署运行包在 `output/campus-server-*`；包内 `README.md` 有完整安装命令。

## 1. 已实现的部署边界

- 一台 PC，一个 Fastify 进程，学校 HTTPS 代理；无需 FTP、Python、CUDA、GPU、Redis 或 PostgreSQL。
- 服务器保存模型密钥，通过现有服务商适配器进行 LLM、ASR、TTS 调用。浏览器只收到业务响应和音频。默认总并发 6、等待 30、每账号单请求、每天 100 次，教师预留一席（并发设为 1 时共享）。每日计数按 UTC 日期，统计请求次数，不是精确 token 或金额账单。
- 师生使用管理员发放的真实账号；同一部署内教师共享教学管理权限。没有学校 SSO、院系多租户或按选课名单限制课程访问。
- 仿真逐步推进、计分与渲染在浏览器运行；课堂数字人使用本地角色素材、动作和音频播放。低性能设备可保留字幕。实时 GPU 推理增强模式仍属于独立开发路线。
- 教师仍手动决定发布、关闭、揭晓和翻页。断网重试不会自动补发教师命令或重新触发 AI。

## 2. 数据、缓存和恢复

`EDU_DATA_FILE` 指定旧 JSON 导入文件，同时作为新 SQLite 文件名前缀。校园首次启动从旧 JSON 导入主状态，保留原文件；后续以 `.platform.sqlite` 为主。账号、参与作答、AI 计数、个人检查点分别使用 SQLite 文件。数据库必须放在服务器本机 SSD，不放在同步盘或网络共享盘。

主业务状态通过事务提交后才对读请求可见；课堂作答、账号和检查点使用 WAL/FULL。心跳和在线连接保持在内存中，重启后通过重连恢复。它们不表示需要永久保存的签到成绩。

浏览器缓存分为基础程序、港口课程、经济数学课程和数字人素材。点击“下载并校验”，只有资源完整并校验通过才标记可离线使用。API 响应不进入 Service Worker 的公共资源缓存；离线阅读进度与已访问的课程信息按账号存于 IndexedDB。退出不会删除个人练习存档；共享机应使用独立系统/浏览器配置，不能把浏览器本地存储视为对同一系统用户加密的保险箱。

首次登录和第一次下载需要联网。已登录设备在会话有效期内（8 小时）可使用缓存课件与个人仿真。缓存课程不意味着能离线执行尚未创建的学习会话、实时课堂指令或云端 AI。失去外网时校园课堂仍可同步；校园服务器不可达时仿真和已缓存阅读继续，服务恢复后补传。

个人仿真约每 30–35 秒同步待传检查点，发送前保存稳定请求编号；丢失回执后重试不会重复产生修订。不同设备有冲突时保留本机版本，用户可导出并明确选择服务器版本。自动恢复仅填充本机不存在的记录。本机计算分数不作为经过服务器复核的正式成绩。

备份前停服，再执行包内 `node admin.mjs backup <新的备份目录>`；该工具导出 SQLite 并检查完整性。恢复也必须停服，并恢复整套数据库。`.env`、证书和发布包另行保护。仅保留数据库中的旧课程版本号不足以完整回放历史教学，必要时一起保留旧发布包。

## 3. 制包与配置

开发机运行 `pnpm install --frozen-lockfile`、`pnpm build:campus`。生成包包含 `server.mjs`、`admin.mjs`、`web/`、`package.json`、`package-lock.json`、配置示例和 PowerShell 工具。部署端运行 `npm ci --omit=dev`，不需要 monorepo 或子模块。

部署前需要填写：

| 配置 | 说明 |
|---|---|
| `EDU_PUBLIC_ORIGIN` | 真实 HTTPS origin，不能带路径或末尾斜杠 |
| Caddy 域名与证书 | 使用学生设备信任的证书；不要用浏览器忽略证书错误代替配置 |
| `EDU_DATA_FILE` / `EDU_PORT_SIMULATION_DB` | 本机数据路径，全部数据库应保持在同一个受保护数据目录 |
| `DASHSCOPE_API_KEY` / `EDU_ASSISTANT_API_KEY` | 服务端密钥，按所用服务商填写 |
| TTS 模型和声音 ID | 未配置时可以使用文字；真实可用性需对服务商验证 |
| AI 并发与请求额度 | 按真实服务商限额、预算和上课方式调整 |

不要复制开发目录的 `.env` 作为生产配置。包内没有默认账户密码。`New-CampusAccount.ps1` 通过隐藏输入创建教师/学生或重置密码，密码不放入命令行参数。服务绑定 `127.0.0.1:4300`，由 HTTPS 代理对校园网开放。使用系统服务托管进程、失败重启，并关闭课堂期间的休眠。

## 4. 本次验收记录

验收脚本不读取工作区真实 `.env`，使用临时数据、随机账号和无网络模型替身。开发机运行 Node 25.8.1、PowerShell 7.6.5、pnpm 11.9.0；其他 Node 版本未作同等实机验证。

- 自动化覆盖：真实账号鉴权、角色与来源限制、会话重启/撤销、SQLite 迁移、写入失败回滚、结束课堂后的迟到 AI、检查点幂等与冲突、AI 容量和取消、浏览器存储与离线进度重试，以及原有课程/互动/仿真测试。
- 浏览器验收：Edge 的生产静态资源；登录、课程下载校验、个人仿真、断网刷新、恢复补传、教师本机数字人、桌面与 390px 页面。截图和结果在 `output/campus-deployment-review/`。
- 课件逐页检查：港口 119 页和经济数学 1,460 页，在 1600px、390px 两种视口共 3,158 次渲染检查，固定画布尺寸、图片、文本画布边界和私有 metadata 属性检查通过。没有把这项布局检查当作所有教学内容的重新审定。
- 本机负载：100 个持久化学生账号、201 条真实 SSE 连接、并发作答/心跳/翻页、断线重连、100 份检查点及同编号重试；脚本 `pnpm test:campus-load`。耗时数据保存在 `load.json`，只反映当前开发机，不作为校园 PC 容量承诺。
- 独立包检查：脚本 `node scripts/verify-campus-release.mjs <发布包目录>`，在包内安装生产依赖，用独立临时数据启动、创建账号、访问生产接口及静态文件，并执行停服备份校验。

这些检查不包含真实校园 VLAN/Wi-Fi、学校证书部署、真实服务商计费/语音调用或学生终端批量兼容性。现场应从教师电脑及学生手机/电脑再演练登录、翻页、作答、缓存、断网恢复及 AI；随后再确定班级规模和限额。
