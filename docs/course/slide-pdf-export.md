# 课件PDF导出

教师课堂、学生跟随课堂、独立阅读和课程预览共用底部工具栏的“导出PDF”。导出面板提供单章、全课程合并PDF、全课程按章PDF的ZIP包；单章默认选中当前页所在章节，可另选已发布章节。全课程指当前已经发布的课件，尚未建设的讲次不生成空白占位页。绪论保留独立章节；存储页码与授课顺序不同的课程按授课顺序导出。

下载采用浏览器原生文件下载，面板显示页数和文件大小。PDF保留1600×1000的16:10画布、可搜索文字、公式、矢量图表和公开来源链接；全课程文件包含章节书签。静态文件呈现已公开教学内容的完整步骤和默认实验参数，视频、动画和实验操作继续使用在线课件。讲稿、助教约束及其他教师元数据不进入导出画布。

## 运行方式

用户点击只请求已生成的静态文件。应用API和课堂控制器不启动Chromium、截图、图片转码或PDF合并，也不在用户浏览器中把全部课件渲染为一个长DOM。按章导出下载一个已有ZIP，不在客户端同时生成或下载几十个PDF。下载链接阻止连续重复点击，并提供明确的重新下载操作。

`pnpm --filter @edu/teacher-web build`在网页生产构建后运行离线生成器。首次准备全部课程耗时较长，发生在备课或构建阶段；后续构建先验证缓存文件的SHA-256，未变的课件复用缓存。生成器根据课程来源、渲染器、样式及资源内容计算指纹，每次发布的清单与网页版本绑定。失败、损坏或未完成的文件不会进入下载清单。

```powershell
pnpm.cmd --filter @edu/teacher-web build
pnpm.cmd slides:pdf:verify
```

网页已构建时，可单独恢复离线生成任务：

```powershell
pnpm.cmd slides:pdf
```

`--courses statistical-analysis`仅适用于局部备课验证；正式发布必须准备完整目录。`build-campus-release.mjs`在创建运行包前检查全部已发布课程的版本、章节、页数、文件大小与SHA-256，拒绝不完整的导出目录。

## 资源保护

- 所有课程共用一个构建进程锁，第二个构建立即退出；没有按用户启动的导出任务。
- 一次只用一个浏览器、一个页面，最多挂载8张课件；每批暂停750ms，清空旧画布并回收内存。浏览器定期重启，在每章压缩与合并前退出，避免浏览器和大文件合并同时占用内存。
- Windows使用Job Object，把构建进程及其全部子进程放入同一个硬限额：整机CPU的10%、总提交内存1536MiB、低于普通优先级。工作进程先暂停、加入限额，再开始运行，避免启动期间越过限制。配置失败就停止构建。
- 可用内存低于768MiB时先等待；持续60秒仍不足就停止。渲染与浏览器协议调用有60秒超时。按批保存检查点，失败后可恢复，而不是并发重试。
- PDF以流方式写入磁盘。大幅、不透明照片适度压缩；文字、公式、矢量图和透明素材保留。ZIP采用存储模式，避免对已压缩PDF再进行高强度压缩。
- Linux/macOS构建使用低优先级、串行批次和额外的JavaScript节流；硬限额由独立构建容器或构建主机提供。校园运行服务器只提供静态下载。

构建需要Chrome或Edge及Python/PyMuPDF。可用`CHROME_PATH`和`EDU_PDF_PYTHON`指定已有运行环境。生成缓存保存在`.runtime/course-pdf-cache/`，生产可下载文件保存在`apps/teacher-web/dist/course-exports/`。开发服务器只读取同一缓存目录中的已验证文件。

课程导出文件不进入自动离线下载清单，也不由Service Worker复制整份PDF或ZIP进内存。普通课件离线包的范围保持原有设置，PDF使用浏览器原生下载。

## 验证

自动检查每张PDF的页数、1200×750pt画布和文字；核对合并文件书签及ZIP目录。导出权限、全部已发布页的章节归属、授课顺序、三种下载范围、过期清单、不安全路径、批次上限和内存等待分别有测试。浏览器检查覆盖桌面与窄屏工具栏、导出面板、实际下载、翻页关闭面板、全屏及课堂控制器连续性。生成后的PDF另作PNG视觉检查，不能用网页预览代替文件本身的检查。
