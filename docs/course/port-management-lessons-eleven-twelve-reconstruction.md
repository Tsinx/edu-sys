## 第11讲 港口绩效诊断与运营改善

### 学习成果

学生能够从挂靠、作业和交付记录中识别主要损失区段，选择可比的观察对象；以等待、履约、成本和未完量联合判断措施；用一次条件匹配的运行对照支持或否定自己的改善假设。

### 真实案例与专业内容

主案例采用新加坡2024年集装箱拥堵。MPA于2024年5月30日说明绕航造成到港失序和船舶集中到达，并公开增配人力、恢复既有泊位与堆场等措施。课堂读取原文中需求变化、到港节奏和处理能力三类证据，研究为什么“装卸量增长”与“等待增加”可以同时出现。[MPA原始说明](https://www.mpa.gov.sg/media-centre/details/in-response-to-media-queries-on--vessels--extended-waiting-times-for-berths-in-the-port-of-singapore)。

基准阅读采用世界银行CPPI 2025入口及2026年6月10日方法说明。重点阅读船型与单次作业量分层、六个时间事件、标准化多年度序列。现有材料只介绍指数名称的内容改为方法阅读任务；使用同版重算序列，不能把不同旧版的分数随意拼接。[CPPI与公开数据入口](https://www.worldbank.org/en/topic/transport/publication/cppi)、[方法说明第2至4页及第8至9页](https://thedocs.worldbank.org/en/doc/855fe5e7123d85b05d4e84c95b8fd1e2-0400012026/original/Methodology-Note.pdf)。

专业知识形成四个可使用的工具：

1. **时间与损失定位。** 识别到港、进港、靠妥、开工、离泊和驶离口岸；区分等待、在泊和全周转。模拟器的到港至驶离口岸时间另行命名，不冒充CPPI原指标。按船型和作业量解释不同时间记录。
2. **波动与拥堵。** 区分平均需求、集中到达、有效能力和资源协同。使用实际队列与作业状态解释等待；不把单服务台近似公式直接套给双泊位、多资源网络。
3. **结果分布与观察窗口。** 计算完成挂靠的中位数及P90，说明最近秩分位数规则；同时保留仍未离港船舶的已等待时间、到期未完货量和样本量。样本太少时直接展示全部记录。
4. **改善评价。** 联合比较进口提离、出口装船、到期按时率、单位完成成本、未完积压和翻箱。将一次运行中的现象、配对运行的差异及可推广结论分开。

### 90分钟安排

| 分钟 | 内容和教师组织 | 学生必须完成的工作 |
|---|---|---|
| 0至8 | 展示新加坡事件的时间、到港与扩能材料，提出经营问题 | 写出两个竞争解释：需求或到港波动变化，与港内某环节受限；分别指出可检验记录 |
| 8至20 | 港口时间事件、有效能力与瓶颈；读取一张挂靠时间图 | 标出三个损失区段，选择优先核查项；不能只凭最长柱子认定责任 |
| 20至33 | CPPI方法阅读及同版样本比较 | 解释为什么按船型、单次作业量分层；用公开数据切片比较趋势与相对位置，说明还需哪项经营证据 |
| 33至45 | 实操A：统一种子与观察终点，完成基准运行 | 保存基准记录；写下预计瓶颈、改动项和预期副作用，保留基准运行文件 |
| 45至63 | 实操B：同船期重练，只改变一项资源安排或明确的一组协同措施 | 操作船舶、货批和调度；在相同模拟时点保存试验记录。多项改动必须如实列出 |
| 63至78 | 对照结果并查阅个别船舶、异常货批和等待原因 | 找出一项改善、一项代价和一项仍不能解释的差异；核对未完成任务是否被平均数隐藏 |
| 78至87 | 运营评审：保留、修改或否定原改善建议 | 用数据解释建议，并回应一位同学提出的替代解释 |
| 87至90 | 提交退出条 | 导出实验记录，写150至250字的结论与下一次验证条件 |

33至63分钟共30分钟实操。第一段结束时保留基准，课间不依靠浏览器继续运行。完整48小时操作不要求在这30分钟内从零做完；后续课件制作必须交付可重放的短练习开局包，把业务窗口压缩在已掌握的操作范围内。

### 三项分析任务

**任务一：提出能被否定的诊断。** 给定等待、货批、资源与时间记录，学生在“岸桥不足”“陆侧接续不足”“到港集中”“手续滞后”中提出一个有证据的主假设，也可以自拟。必须写出哪项观察会推翻自己的判断。教师参考答案包含多个可能成立的诊断，由记录决定。

**任务二：比较同预算或同资源总量的措施。** 一组保持设备不变调整岗位，一组改变设备配置并计入成本；采用同一船期种子和观察终点。保存各自记录后交换结论。班级同学的记录是重复验证材料，不能把不同种子的高分直接排成措施优劣榜。

**任务三：审查一份看起来漂亮的报表。** 选择一份已完成平均时间下降、但未完积压上升的运行记录；若真实运行未产生该现象，就使用明确标注的独立教学数据。学生修正报表，并解释为什么仅看完成样本会误判。不得把设想中的现象写成模拟器必然结果。

### 评价

诊断与证据30%，实验设计25%，结果解释30%，可复核记录15%。措施没有改善也可获得高分；隐瞒未完量、混用时点或未披露多项改动应降低相应项得分。此为新教学任务量规，不直接改写现有模拟器的100分评分规则。

## 第12讲 港口风险屏障与中断恢复

### 学习成果

学生能够区分事件、直接机制和组织管理失效；为一个具体风险画出威胁、顶事件、后果与屏障；在模拟故障或异常箱出现后保持其他业务运行，记录处置依据、影响范围和恢复所需证据。

### 真实案例与专业内容

主案例采用天津港“8·12”瑞海公司危险品仓库事故调查报告。选取企业安全管理、监管接口、评估与整改等相关段落，以“为什么多道制度与检查没有形成有效屏障”为主问题。使用报告第27页起的企业问题和第90至95页的教训与建议，不将历史引用的法规条号当成现行条文。[应急管理部保存的原始调查报告](https://www.mem.gov.cn/gk/sgcc/tbzdsgdcbg/2016/201602/P020190415543917598002.pdf)。

对照案例采用名古屋港2023年7月NUTS系统中断。国土交通省公开材料记载，集装箱搬入搬出停止约三天。课堂据此区分系统可用、数据可信和物理作业能力，分析业务连续性；不把闸口中断等同于全港所有作业停止。[国土交通省案例与委员会资料](https://www.mlit.go.jp/kowan/kowan_mn2_000006.html)、[运营方当月通知索引](https://meikoukyo.com/archives/date/2023/07)。

本讲的专业工具是屏障分析与业务影响分析：

1. **蝴蝶结分析。** 威胁在左，失控顶事件居中，后果在右；预防屏障与减缓屏障分别标明。每道屏障注明实际作用、依赖条件、验证证据和责任接口。图由学生建立，教师随后展示可辩护的版本。
2. **共同原因失效。** 多个签字、检查或系统若依赖同一份错误资料，就不能简单视为独立防线。学生必须找出依赖关系，不能用相乘的任意小概率制造安全结论。
3. **信息与物理作业耦合。** 区分信息不可获得、过期、错误，以及设备实际不可用；沿货批、闸口、堆场与船舶查找影响传播。
4. **连续性与恢复。** 区分恢复时间目标、可接受数据损失窗口与实际恢复证据；先核对哪些业务可继续、哪些须隔离，再验证任务和记录是否一致。课堂不提供危险货物操作参数或生产系统恢复指令。

屏障图法参考[英国民航局的Bowtie要素说明](https://www.caa.co.uk/safety-initiatives/working-with-industry/bowtie/bowtie-elements/)，采用分析方法，不移用航空运行规则。恢复时间目标和恢复点目标的术语参考[NIST的RTO定义](https://csrc.nist.gov/glossary/term/recovery_time_objective)及[RPO定义](https://csrc.nist.gov/glossary/term/recovery_point_objective)；由港口业务后果确定教学目标，不把通用定义当成港口统一限值。

### 90分钟安排

| 分钟 | 内容和教师组织 | 学生必须完成的工作 |
|---|---|---|
| 0至10 | 天津事故证据摘页，先展示当时事实与相关职责 | 将材料分为事件事实、管理安排和调查结论；避免用事后结论填回事前判断 |
| 10至23 | 从一条事故链建立蝴蝶结图 | 给出两道预防屏障、一道减缓屏障；每道都标出验证材料与依赖条件 |
| 23至35 | 名古屋系统中断及业务影响图 | 指出信息故障怎样传到闸口、堆场与交付；提出一个能检验的恢复条件 |
| 35至45 | 实操A：在现有模拟港定位一项已经发生的异常 | 保存当时故障、异常箱或被拒业务记录；写出工作假设、影响对象和待办顺序 |
| 45至65 | 实操B：实际办理核查、调整资源或安排维修，并维持其他作业 | 使用既有业务表单执行处置；记录前后状态、等待、积压和新增成本；禁止用勾选清单直接宣告恢复 |
| 65至78 | 复盘与恢复评审，交换一项新材料 | 用实际状态复核原假设，区分故障消除、单项条件满足和整个任务完成；更换场次时保留原记录 |
| 78至87 | 管理评审：哪项措施最能避免再次发生 | 选择一项有责任接口、可验证证据和复查触发条件的整改；回应共同原因失效的质询 |
| 87至90 | 提交退出条 | 导出事件复盘，附屏障图和150至250字处置说明 |

35至65分钟共30分钟实操。个人在一台电脑上轮流承担调度、货批与交接职责；角色切换不重开场次。可交换同学的证据进行质询，但不要求新增联网分组系统。

### 两项实操任务

**任务一：故障条件下持续运营。** 教学开局需保留实际在制任务和货流，再触发既有岸桥故障。学生比较立即组织维修、先转配岗位与设备、保持非受影响作业三类动作的次序。评分关注受影响对象是否识别准确、措施是否确实生效、是否把风险转给其他环节，以及证据是否能重放。

**任务二：异常箱与交接。** 从真实运行中选择已发现的异常箱，查阅位置、货批和核查状态，使用既有送检与委托核查流程；观察它与正常箱流的区别。下一份证据可证明某项异常已解决，也可能只表明信息已送达。学生必须说明这次变化究竟改变了哪项判断。

名古屋案例用于分析真实信息中断；当前模拟内核没有NUTS故障模型，不能将现有岸桥故障冒充网络攻击。信息中断、备用记录与积压恢复作为后续扩展任务单独实现和验证。

### 评价

事件与证据定位25%，屏障分析25%，处置与恢复验证30%，业务连续性和责任交接20%。仅写“安全第一”“继续核查”不得获得分析分；未发生事故也不能直接证明屏障有效。

## 课件制作清单

每讲预计28至34个画面，保留1600×1000画布与教师控制揭示。第11讲配置真实事件图、时间口径图、分层样本、完整挂靠分布、等待原因、资源网络、实验任务与结果评审。第12讲配置调查证据、事实时间线、学生可编辑屏障图、共同原因依赖、业务影响图、事件实操与恢复评审。

课件中的每张页面必须贡献新材料、一个可使用的专业工具、一次必要的推导或一个有新约束的判断。删除重复的过渡总结和只把一句话分成几个框的页面。真实事件、真实报告数据与独立模拟运行三类材料用短标签区分。

制作时同时交付两个短练习开局文件、教师参考分析、学生任务单、来源摘页与本地备用材料；逐个核对运行时长。正式更新课程页序、教师讲稿、助手上下文、资源入口和PDF时同步迁移，不能只换标题而保留旧的48页定位。

## 模拟系统更新

### 本轮配套实现

在现有48小时综合实训的业务工作台增加“实验分析”，供学生在当前运行中使用。

| 功能 | 学生操作 | 证据与边界 |
|---|---|---|
| 固定观察终点 | 在教学模式设置第几小时停止，运行到该时点自动暂停 | 工作线程按剩余秒数推进；不改实战模式的计时和评分 |
| 实际运行指标 | 读取完成与未完成挂靠、周转分布、等待、到期履约和成本 | 仅使用学生当前可见记录，潜在异常及未公布到港不进入分析 |
| 基准与试验记录 | 暂停后保存基准，同船期重练后保存试验 | 检查种子、到港配置、业务版本、观察时点、任务队列及场次；匹配不等于自动取得因果解释 |
| 原始证据阅读 | 查看逐船结果和未完成状态，保留成本与资源条件 | 未完成船不填零，不混入完成样本分位数；成本以教学成本单位表示 |
| 风险复盘 | 从当前故障、已发现异常箱和操作记录中固定一份证据，写假设、屏障、处置与恢复标准 | 后续状态来自同一业务内核，分析卡不能放行业务或自动完成核查 |
| 记录与导出 | 本地保存实验草稿，导出JSON及逐船CSV | 导出学习证据，不携带身份、登录凭据、隐藏答案或未来状态 |

本轮实验分析模块与既有业务操作共同构成两讲的操作基础；短练习开局包、正式课件重写、教学任务提交与教师量规评分仍按上面的制作清单完成。已有模拟成绩和历史复盘文件沿用其原规则。

### 后续完整教学版本

后续在同一内核上制作短练习开局与明确版本的任务包，补齐共同检查点分支、可控的教学信息中断、有限容量的备用记录与恢复积压，以及教师按上述量规复核的入口。新增中断必须改变实际作业条件，并能通过重放复现；不以弹窗或任意扣分冒充经营影响。

## 验收

内容验收首先检查案例原文、专业概念和推理链，再试讲两段45分钟。至少一名学生须在规定实操时段内独立完成基准、试验或事件复盘；若操作占时过长，调整开局和任务范围，不靠教师替学生完成。

系统验收检查真实指标计算、空样本和未完任务、相同时点停止、条件不匹配提示、同场次复核、刷新恢复、文件导出、桌面与窄屏、键盘输入和全屏连续性。课件实施后另跑学生文案审计、助手上下文测试、类型检查、生产构建和浏览器全讲检查。

来源核验日期为2026-10-14。课堂正式材料应保存明确版本和报告页码；公开资料的历史事实与本课程自行设计的任务、评分和模拟参数分别归档。
