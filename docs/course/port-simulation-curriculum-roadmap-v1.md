## 1. 路线图目标与边界

路线图服务三个目标：

1. 让学生用可复现证据解释港口作业链、瓶颈、绩效和韧性；
2. 在不放松安全约束的前提下，公平比较人工、规则和 AI 策略；
3. 即使未来软件尚未完成或课堂网络故障，16 讲仍能达到同一学习成果。

本路线图不修改现有第 1—3 讲、119 页课件或运行代码。本文中的“计划能力”只有通过对应验收门后才可改标“当前可用”。教学仿真始终是概念模型，不连接真实港口设备，不提供实时 AIS、生产 TOS／PCS、工程、导航、危险货物或安全控制服务。

## 2. 当前 V1.0 已验证基线

### 2.1 交付方式

| 项目 | 当前事实 | 课程含义 |
|---|---|---|
| 默认模式 | 登录后的本地单机 local_solo | 服务器确认身份并读取课堂挑战；运行状态不代表服务器认证结果。 |
| 权威状态 | 浏览器中的共享确定性核心负责命令校验、时钟推进、计分、事件和回放 | SVG 动画与界面只投影状态，不得反向决定业务完成。 |
| 岗位 | 港调／VTS、泊位与岸桥、水平运输、堆场与闸口 | 单名学生可轮换四岗位；它们是教学角色，不等于现实法人责任。 |
| 场景 | 双教学船、7 个泊位、6 台岸桥、4 台 AGV、24 个堆场块、2 条闸口通道；12 小时教学时域 | 所有船名、任务、时刻和资源配置均为虚构教学情境。 |
| 功能参照 | 场景结构说明引用洋山四期自动化码头 | 只作功能教学示意，非工程图、导航图或生产参数。 |
| 挑战 | 第一次联合值班、稀缺岸桥的选择、故障与高峰叠加 | 分别用于第 4、5、15 讲；第 3、6、11 讲使用同一运行器做入门、接口或绩效审计。 |
| 复合事件 | 04:30 AGV-03 故障 60 分钟；06:00 外集卡集中到达 | 固定事件脚本，只证明该情境内的响应，不代表现实概率。 |
| 诊断分 | 1000 分：安全 250、完成 250、船舶流 200、资源协同 150、事件恢复 100、岗位参与 50 | 只用于解释与自我比较；不直接计入正式课程成绩。 |
| 存档 | 当前浏览器本地保存最近 30 轮，界面显示最近 5 轮和同案例历史最佳 | 换设备／浏览器可能不可用，不是课程成绩库。 |
| 复盘 | 可导出不含姓名、登录标识或外部学号的 JSON；确定性事件回放和状态哈希可用于校验 | 可作为项目证据候选，但需人工提交并在未来服务端复算后才可认证。 |
| 网络边界 | 页面载入后不上传业务命令、快照或分数；网络中断不终止已载入运行 | 教师不能实时监控、暂停或接管学生本地过程。 |

### 2.2 当前可做与不能做

当前可以：

- 认识完整集装箱码头链、角色职责和合法动作；
- 比较同一确定性情境中的人工方案；
- 查看等待、阻塞、资源、事件恢复和诊断分；
- 导出运行并用事件序列解释结果；
- 体验不安全命令被拒绝、低效但安全动作产生后果。

当前不能：

- 由服务器认证或重算本地分数；
- 自动收集学生运行、形成正式排行榜或课程成绩；
- 参数化分发任意情境、固定种子批量运行或导入他人运行；
- 模拟其他货种、现实成本、排放、气象、治理、港城约束；
- 训练或执行 PPO 等 AI 策略；
- 声称使用真实港口实时数据或生产接口。

## 3. 课程使用总原则

1. **引擎权威。** 业务状态与指标来自共享核心；动画、按钮次数和口头陈述都不是完成证据。
2. **安全优先。** 禁止动作、授权和硬安全约束进入环境与合法动作集合，不能用奖励扣分替代。
3. **分数降级。** 综合分只提供快速反馈；正式报告必须展示原始指标、事件证据、版本、种子和局限。
4. **方案预注册。** 运行前记录情境、策略、权重、种子集合、停止规则和成功／失败判据；运行后不能静默改规则。
5. **同条件比较。** 人工、规则和 AI 使用相同可见信息、合法动作、情境版本、测试种子、时限和指标。
6. **人类确认。** 正式课堂中 AI 默认只给可解释建议，由学生确认；连续自动执行仅限独立实验沙箱。
7. **现实参数有出处。** 每个参数标“官方观测、文献估计、由来源推导、教学设定、未知”之一。
8. **随时可降级。** 每讲都有纸面或预生成运行包，不把学习目标绑在尚未完成的软件上。

## 5. 第一阶段：实验与证据能力

### 5.1 目标

在不改变 V1.0 核心教学逻辑的前提下，把“某学生本机跑出一个分数”升级为“可分发、可导入、可重放、可比较、可由同版本引擎复算的实验”。

优先支持第 3—6、11、15 讲；这是课程能否严肃使用仿真的最先决阶段。

### 5.2 最小交付

1. **参数化情境清单**
   - 情境 ID、版本、核心引擎版本、挑战版本；
   - 参数值、单位、来源类型和允许修改范围；
   - 事件脚本或随机种子；
   - 适用讲次、目标和禁止用途。

2. **固定种子作业单**
   - 教师创建不可变作业 ID；
   - 学生收到相同基准种子和组内不同复现实验种子；
   - 作业结束前不公开隔离测试种子。

3. **运行导入／导出与回放**
   - 导出完整事件链、初始清单、策略描述、指标和状态哈希；
   - 导入前验证模式、版本、哈希和个人数据最小化；
   - 回放只读，不把旧事件重新当实时命令发送。

4. **方案对比**
   - 选择两至四个运行包；
   - 按原始指标、事件时间线和状态转折对齐；
   - 显示参数／策略差异，禁止只显示总分差。

5. **事件证据包**
   - 关键决策、被拒动作、状态前后、等待来源、故障与恢复；
   - 教师和学生可为关键事件添加解释，但解释与引擎事实分层保存。

6. **服务端确定性复算**
   - 学生主动提交运行包；默认不持续上传本地过程；
   - 服务器按清单指定的核心版本从初始状态重放；
   - 验证终态哈希、事件序号和原始指标；
   - 返回可验证回执，不直接把分数写入正式成绩。

### 5.3 建议数据契约

运行包不含姓名、学号、登录 token 或浏览器指纹。身份与运行的课程归属由提交记录在服务端另表关联，导出的公开证据包使用匿名运行 ID。

### 5.4 复算流程

    教师发布不可变作业清单
        → 学生本地运行并导出
        → 客户端完成 schema、版本和哈希预检
        → 学生明确确认上传
        → 服务器选择清单锁定的核心版本重放
        → 对比终态哈希和原始指标
        → 生成复算回执
        → 报告引用 runId 与 receipt，而非截图

### 5.5 第一阶段验收门

- 同一清单、种子和事件链在支持环境中得到相同终态哈希和原始指标；
- 任一事件篡改、顺序缺失、版本不匹配或非法动作均被拒绝并给出原因；
- 比较页至少显示六类原始指标、关键事件和控制变量；
- 断网时本地运行不丢失，恢复后由学生主动提交；
- 复算服务不执行客户端任意代码，只解析白名单 schema 与已部署引擎版本；
- 导出包不含直接个人标识；
- 本地分数仍明确标为诊断，不进入课程正式成绩字段。

## 6. 第二阶段：情境工作台

### 6.1 目标

让教师在统一证据规范下扩展货种、需求、成本、排放、气象、治理和港城约束。工作台不是自由修改所有数值的“上帝模式”，而是版本化的教学情境编辑、审查和发布工具。

### 6.2 情境分层

| 层 | 内容 | 首要课次 |
|---|---|---|
| 网络与需求 | 航线、港序、腹地、用户细分、到港／货流不确定性 | 2、8、10、15 |
| 船舶与货种 | 集装箱、干散货、液散、滚装、冷链、客运、危险货物的抽象属性 | 4、7、12 |
| 设施与资源 | 泊位、岸桥、装卸机、管线／罐区、堆场、车辆、铁路、驳船、闸口 | 4—8 |
| 作业与信息 | 状态机、前置条件、TOS／PCS／单一窗口信息事件 | 4—7、13 |
| 经济 | 固定／变动成本、收费、时间与库存成本、分期投资 | 8—11、16 |
| 环境与能源 | 活动量、能源、排放因子、岸电、替代燃料、天气 | 8、14、15 |
| 治理与港城 | 产权／经营、合同义务、监管、劳工、社区暴露、交通和土地 | 9、10、12、14、16 |
| 扰动与恢复 | 到港波动、设备故障、闸口高峰、气象、信息失效 | 12、15 |

### 6.3 参数来源约束

每个参数对象必须包含：

    parameterId
    label / value / unit
    scope / period
    provenanceType:
      official_observation
      literature_estimate
      derived
      teaching_assumption
      unknown
    sourceId?
    transformation?
    uncertainty?
    allowedUse
    prohibitedUse
    reviewedAt / reviewer

发布门规则：

- official_observation 和 literature_estimate 必须有关联来源、对象、期间和单位；
- derived 必须保留原始值与换算公式；
- teaching_assumption 必须在学生界面可见“教学设定”标签及其教学理由；
- unknown 不得静默替换为 0 或行业平均值；
- 法定限制和安全边界只能由审核过的规则包提供，普通情境作者不能放宽；
- 真实地名可用于案例，虚构船舶、货量和事件不得混入官方字段。

### 6.4 货种插件最小模型

| 货种 | 必须表达 | 明确不做 |
|---|---|---|
| 集装箱 | 箱流方向、箱类、装卸、水平运输、场位、闸口／铁路／驳船 | 真实箱号、实时堆场或商业舱单 |
| 干散货 | 批量、装卸速率、堆场／筒仓、粉尘与交叉污染约束 | 工程输送系统设计 |
| 液体散货 | 船岸界面、管线／罐区状态、相容与隔离的抽象硬约束 | 真实化学品配载、阀门或应急操作 |
| 滚装 | 车辆流线、舱面／堆场、交付节奏和损伤风险 | 真实船型配载与交通控制 |
| 冷链 | 温控状态、断链时间、检验与优先级 | 食品安全认证或设备设定指令 |
| 客运 | 旅客、行李、车辆、人流分隔和应急容量 | 保安布置、疏散工程设计 |
| 危险货物 | 类别标签、授权、隔离、停工和升级的教学抽象 | 危险品具体配装、消防、处置或操作参数 |

### 6.5 作者—审核—发布流程

    草稿
      → schema 与单位检查
      → 来源和现实／教学边界检查
      → 安全规则审查
      → 固定种子回归
      → 教师试讲
      → 发布不可变版本
      → 归档与退役

已发布情境不可原地改写。修正任何参数、规则、来源或指标都会生成新版本，并记录变更说明与受影响课次。

### 6.6 第二阶段验收门

- 至少完成集装箱之外两种货种的教学插件，其中一项为非连续件货；
- 同一现实参数在界面、导出包和报告中保留相同来源 ID、单位和期间；
- 教学设定有醒目标识，无法导出为“官方观测”；
- 分期、成本和排放结果可追溯到输入、公式和指标版本；
- 安全规则包不能由普通情境权重覆盖；
- 每个计划软件实验都有对应纸面任务与预生成结果包。

## 7. 第三阶段：Agent Lab

### 7.1 目标

Agent Lab 用于比较决策方法，不追求替代真实港口调度员。环境沿用共享确定性核心，并把观察、合法动作、执行结果和安全约束作为稳定契约。

### 7.2 环境接口

    reset(config, seed) -> ResetResult
      observation
      legalActions
      stateDigest
      metricState

    observe(agentId) -> Observation
      visibleState
      clock
      queues
      resourceStatus
      pendingEvents
      dataQualityFlags

    legalActions(agentId) -> LegalAction[]
      actionId
      actionType
      parameters / allowedRanges
      prerequisites
      safetyClass
      explanation

    step(action) -> StepResult
      accepted
      rejectionReason?
      nextObservation
      nextLegalActions
      rawMetricDelta
      emittedEvents
      terminated / truncated
      stateDigest

环境要求：

- reset 后同版本、同种子得到相同初始状态；
- observation 只含该策略被允许看见的信息，不能从 UI 或调试字段泄漏未来事件；
- legal actions 是环境权威集合，策略输出必须先通过 schema 和动作掩码；
- step 不接受绕过正常引擎的状态写入；
- 安全拒绝写入事件证据，但奖励函数无权将非法动作变为合法；
- 终止、时间截断、死锁和安全停机分别记录。

### 7.3 安全与动作掩码

硬约束分三层：

1. **物理／状态约束**：资源占用、轨位间距、船舶阶段、容量和动作前置条件；
2. **授权约束**：只有相应角色或实验代理可提议动作；正式课堂仍需学生确认；
3. **安全规则包**：禁止动作、停止条件、隔离和恢复证据。

策略只能在 legal actions 中选择。若模型返回越界参数、未知动作或被掩码动作，环境拒绝并记录；训练代码不得通过负奖励“学习着偶尔违反红线”。

### 7.4 指标与奖励版本化

环境始终输出以下原始指标，不因奖励权重改变：

| 维度 | 例示原始指标 |
|---|---|
| 安全 | 非法动作提议／拒绝数、硬约束触发、停机、恢复前证据完整度 |
| 周转 | 船舶等待、在港时间、任务完成时间、货物端到端时间 |
| 资源 | 忙、闲、阻塞、移动、充电、队列、瓶颈迁移 |
| 成本 | 运营、时间、库存、能源、罚则的情境成本及币种／基期 |
| 排放 | 活动量、能源和边界明确的情境排放 |
| 韧性 | 性能损失面积、恢复时间、尾部等待、跨扰动成功率 |

奖励说明独立保存为 RewardSpec：

    rewardSpecId / version
    objectiveTerms[]
    normalization[]
    scalarWeights[]
    constraints[]
    terminalTerms[]
    knownFailureModes[]
    approvedBy / approvedAt

任何权重、归一化、终止奖励或惩罚变化都生成新版本。报告必须同时展示原始指标和奖励版本，禁止只报告累计奖励。

### 7.5 对照策略

| 策略 | 必备实现 | 课程用途 |
|---|---|---|
| 人工策略 | 学生在建议界面确认动作，保留理由和事件 | 作为可解释的主要基线 |
| 规则策略 | 至少提供 FIFO／安全优先／瓶颈保护等公开规则，版本固定 | 识别简单启发式能解决什么 |
| 预训练掩码 PPO | 在动作掩码下训练，发布模型卡、训练清单、奖励版本和测试结果 | 研究多目标与泛化，不作为权威答案 |
| 自定义编码策略 | 选修沙箱；只能调用稳定环境 API | 服务有编程能力学生的拓展研究 |

不得用弱化的人工时间限制、额外的 AI 观察或不同测试种子制造不公平优势。若规则策略在某情境更稳健，课程应如实呈现。

### 7.6 训练、验证与测试隔离

- 以情境族为单位建立不可重叠 seed manifest；
- 默认划分 60% 训练、20% 验证、20%隔离测试；
- 测试种子和扰动参数只保存在评测服务，策略选择结束后才运行；
- 同一测试集不得在反复调参中循环使用；每学期轮换或建立新的锁箱测试集；
- 除同分布测试外，至少包含一个货流、设备能力或扰动组合不同的跨情境测试；
- 人工和规则策略使用相同隔离测试，允许的交互时间和信息一致；
- 训练随机种子、环境种子和模型初始化种子分别记录。

### 7.7 评价报告

每个策略至少报告：

- 每个原始指标的均值、标准差／四分位距、最差分位或范围；
- 硬约束违例与非法动作提议，按运行数和机会数同时给出；
- 完成率、截断率、死锁和安全停机；
- 基准、扰动和跨情境泛化差异；
- 对权重、需求和故障的敏感性；
- 计算／训练成本和决策延迟；
- 典型成功轨迹与失败轨迹各一条；
- 与人工、规则基线的同条件差异，而非单次最高分。

若样本不足以做稳定推断，报告“探索性结果”，不包装成显著优势。

### 7.8 无代码学生界面

所有学生可：

- 选择已批准情境和策略；
- 在安全硬约束之外调整周转、资源、成本、排放、韧性权重；
- 在运行前查看权重变化会强调什么、可能牺牲什么；
- 选择“建议—解释—确认”，拒绝建议时记录理由；
- 比较多种子结果、关键事件、原始指标和失败轨迹；
- 导出匿名证据包与复算回执。

界面不能提供“关闭安全规则”开关。全自动按钮仅在明确标识的独立沙箱、非正式课堂运行、无生产连接条件下出现。

### 7.9 模型卡与可解释建议

每个预训练策略随附：

- 用途与不适用范围；
- 环境、情境、观察与动作版本；
- 奖励版本与硬约束；
- 训练、验证、测试清单摘要；
- 基线、均值、波动、违例和泛化结果；
- 已知奖励投机与失败情形；
- 训练日期、代码／模型版本和计算预算；
- 正式课堂默认建议模式。

建议至少回答“建议做什么、依据哪些可见状态、合法动作证据、预计改善的原始指标、可能恶化什么、何时不适用”。解释是审计信息，不等于因果保证。

### 7.10 第三阶段验收门

- 接口契约、动作掩码和确定性环境通过回归；
- 任何非法动作都不能由奖励或模型权限放行；
- 人工、规则和 PPO 使用同一隔离测试与可见信息；
- 训练／验证／测试种子无交叉，测试锁箱有审计记录；
- 报告包含分布、违例、失败轨迹和跨情境结果；
- 模型卡、奖励版本、环境版本和复算回执齐全；
- 默认课堂流程必须经过学生确认；
- 关闭 AI 后课程仍能用规则与纸面活动完成。

## 8. 课程优先级与依赖

| 优先级 | 建设项 | 依赖 | 解锁课次 | 未完成时处理 |
|---|---|---|---|---|
| P0 | 保持 V1.0 现有确定性核心、回放和本地边界稳定 | 当前测试与版本治理 | 3—6、11、15 | 使用当前版本或纸面包 |
| P1 | 作业清单、运行包、导入回放、方案对比、服务端复算 | schema、版本仓、复算隔离 | 3—6、11、15、16 | 本地导出 + 人工证据审计 |
| P2 | 参数来源登记和情境工作台基础 | P1 运行包、证据台账 | 7—10、14、15 | 结构化纸面情境 |
| P3 | 成本、排放、气象、治理和港城模块 | P2、方法审核 | 8—10、14、16 | 表格与多准则矩阵 |
| P4 | 稳定环境 API、规则策略和无代码比较 | P1 确定性复算、P2 情境版本 | 13、15、16 | 人工规则对照 |
| P5 | 掩码 PPO、测试锁箱和模型卡 | P4、安全审查、评测服务 | 13、16 | 预生成 AI 运行包或取消 AI 比较 |

P1 是最高新增优先级；在可复现与来源能力完成前，不应先建设排行榜或复杂训练界面。

## 9. 无软件活动包

每讲备用包采用统一结构：

1. 情境封面：学习目标、角色、现实／教学边界；
2. 初始状态：资源、队列、时刻、未完成任务；
3. 合法动作表：前置条件、直接结果、禁止动作；
4. 固定事件信封：按统一时间点开启；
5. 状态—动作—结果记录表；
6. 原始指标字典与计算表；
7. 至少两条预生成完整轨迹；
8. 复盘问题：预测错误、瓶颈迁移、安全红线、反证；
9. 来源卡：现实资料 ID 与禁止外推；
10. 教师答案边界：允许结论、不能据此判断的结论。

纸面包与软件使用相同概念、指标和评价量规。软件不可用时，不降低证据、推理或复现要求。

## 10. 质量、隐私与安全验证

### 10.1 核心回归

- reset、step、回放和复算的状态哈希一致；
- 时钟、事件顺序、重复命令、边界时刻和版本迁移可预测；
- 动作掩码覆盖 UI、规则、AI 和导入事件四条路径；
- 指标与奖励分离；改变奖励不改变相同轨迹的原始指标；
- 已发布情境、奖励和模型版本不可被静默覆盖。

### 10.2 实验 QA

- 种子清单无重复和跨集合泄漏；
- 人工、规则、AI 的观察字段和时限可审计；
- 比较结果包含失败与尾部，不选择性只报最好运行；
- 单位、币种、价格基期、排放边界和统计窗口在导出中保存；
- 教学设定在 UI、运行包和报告中保持标签。

### 10.3 隐私与安全

- 本地运行默认不上报；上传需明确动作和目的说明；
- 公开运行包只使用匿名运行 ID；
- 服务器按白名单 schema 解析，不反序列化任意对象或执行策略代码；
- 自定义策略在资源受限沙箱运行，无外网、生产凭证或文件系统权限；
- 训练产物与课程身份分库存储，设定最短合理保留期；
- 操作日志用于复现和安全，不把“操作多”作为参与度或成绩代理。

### 10.4 教学可用性

- 桌面与窄屏均能查看状态、合法动作、来源和错误原因；
- 键盘操作、减少动态效果和无动画复盘可用；
- 软件登录／加载时间不计入 90 分钟核心活动；
- 教师能在课前用固定作业执行一次端到端演练；
- 任一远程服务故障时能在 5 分钟内切换到无软件包。

## 11. 版本与变更治理

以下对象独立版本化，不能只用一个“课程版本”覆盖：

- 课程与讲次；
- 场景和参数集；
- 挑战与任务；
- 核心引擎；
- 环境 API；
- 指标规范；
- 奖励规范；
- 人工／规则／AI 策略；
- 训练、验证、测试 seed manifest；
- 运行包与复算回执；
- 来源台账。

任何变更记录：变更原因、影响课次、向后兼容、复现实验影响、来源更新、安全审查和回滚方式。旧项目报告所引用的运行包必须仍能由相应存档引擎复算；若不能，明确标为“历史不可复算”而不是用新版本替换结果。
