# 课堂助教本地语音唤醒

教师在数字人面板选择“检测输入”，点击“开启语音唤醒”并允许麦克风访问。
每次进入课堂需要手动开启；打开页面不会自动启动麦克风。

“检测输入”内可选择“原始模型”或“个人微调模型（试用）”。首次默认原始模型，
选择保存在当前浏览器；刷新页面或切换输入方式后继续使用所选模型，但不会自动
开启麦克风。监听开启期间不能更换模型，请先关闭监听再选择并重新开启。
模型加载失败会关闭监听并提示，可切回原始模型。

个人微调版使用2026-09-09训练的 FP32 ONNX 权重，针对“你好助手／非常感谢”录音
进行了局部微调。它与原始模型共用口令、录音控制逻辑和本地VAD。新增短“谢谢”
在两种选项中都用通用权重检测，并同时检查音节时长及近期人声；个人微调权重
继续负责唤醒和明确结束，取消与续语保护也使用通用权重。这样避免未专门训练的
短词在微调图中误报静音。
这是可供现场比较的试用选项，小样本结果不保证课堂误报率或召回率。

| 操作 | 默认口令 | 兼容名称 |
| --- | --- | --- |
| 开始录制本轮指令 | 小麦老师 | 你好助手、你好小助手、助教你好、澜舟你好 |
| 结束并发送 | 谢谢助教、非常感谢 | 谢谢澜舟 |
| 确认说完后发送 | 谢谢 + 约1秒停顿 | 确认前继续说话则继续本轮 |
| 放弃本轮录音 | 助教取消 | 澜舟取消 |

例如：“小麦老师，请进入第二讲，非常感谢。”可以连说，也可以在唤醒后停顿。
也可以说“小麦老师，请进入第二讲，谢谢”，然后停顿。未唤醒时，说“谢谢”不会发送。
录音开始后关闭唤醒词检测，待结束期间也不重开；再次称呼“小麦老师”属于本轮内容。
明确结束词“非常感谢／谢谢助教／谢谢澜舟”仍是保留口令，不宜在问题中引用。
单独“谢谢”只进入“正在确认是否说完”，本地Silero VAD确认连续约1秒无人声后
才结束并发送；确认前重新说话会取消待结束状态，保留已录内容继续收音。
取消待结束后，后续单纯停顿不会自动发送，需要再次说结束词。
本地模型按发音检测，澜舟的同音写法不需要另外加入模型。

## 三种输入统一

翻页、跳转课次、切换活动等纯操作指令静默执行，仅在界面显示结果，不朗读
“好的”“已翻页”等确认语。提问和讲解继续语音回答；明确要求“翻页并讲解”时，
既执行动作，也播报教学正文。地球仪自身的预设讲解不受操作确认静音影响。

课堂助手先输出 `replyKind`：`control` 不向TTS发送任何文字，`answer` 保持流式
教学回答。未带该字段的旧格式响应等待完整校验后再决定是否播报，有动作时抑制
附带确认语；课堂动作仍须在完整JSON校验通过后执行。学生课下问答流程保持原状。

课堂开始后可选择“检测输入”“按键输入”“文字输入”。按键输入按一次开始录音，
再按一次结束并发送；也可点击“取消本轮”。检测到唤醒词与按键开始调用同一录音
状态逻辑，检测到结束词与第二次按键调用同一结束逻辑。两种录音均为16kHz PCM，
结束后通过平台 `/api/teacher/asr` 识别，不依赖 LAM 连接。按键方式不加载关键词
模型，也不清理用户说出的保留口令。两种方式60秒未结束都取消本轮，不自动提交。

语音转写和文字共用指令校验、防重复提交及课堂助手入口；语音来源记录为
`voice_asr`，文字为 `text`。三种方式在助手回答期间暂停提交。切换输入方式会取消
尚未完成的录音或识别；课堂结束、离开页面和延迟授权也不会恢复旧录音。

全屏切换及收起数字人只改变显示方式，不重建输入组件：输入方式、未发送文字和
监听/录音状态保持不变。小窗和收起后的控制条保留收音按钮；按键输入可直接开始、
结束并发送或取消本轮，检测输入可直接开启或关闭监听。
切换到另一个课堂仍创建新的输入会话。

## 本地检测与录音

`classroom-keywords.js` 在浏览器 Web Worker 中运行 sherpa-onnx 1.13.7 的
WebAssembly 运行时和 WenetSpeech Zipformer 3.3M 中文关键词模型。使用 CPU，
不依赖 LAM GPU 服务。底层是小型语音网络加关键词约束解码，接口仅输出白名单
关键词，不进行待机语音的全文转写，也不使用浏览器云端 SpeechRecognition。

AudioWorklet 提供单声道16kHz音频。待机只检测唤醒口令，录音期间只检测结束与
取消口令；待机语音不上传。Silero VAD在同一Worker中运行，每32ms处理一窗音频，
使用语音活动判断而非音量阈值决定短“谢谢”是否结束。VAD模型与KWS一起常驻，
断开收音时仅重置流状态。模型安装来源见 [sherpa-onnx Silero VAD文档](https://k2-fsa.github.io/sherpa/onnx/vad/silero-vad.html)。
只在内存保留4秒回看音频以补偿唤醒检测延迟。唤醒后使用浏览器连续音频时钟
和关键词声学时长保留短暂唤醒上下文（上限4秒），避免丢失紧接着说出的指令。
该上下文可能包含唤醒词前的一小段声音；仅确认结束本轮后才随录音上传。
模型的内部时间戳会因检测命中或静音而重置，不能直接作为连续录音的绝对下标。
检测到结束词后先停止麦克风并断开音频到检测器的通道，再向 `/api/teacher/asr`
发出一次识别请求；模型权重及WASM运行时保留在当前监听会话的Worker中。
转写后清理开头唤醒词及明确结束词；短“谢谢”仅清理末尾，保留中途“谢谢”后继续
说的内容和录音中重复的“小麦老师”称呼。录音与缓冲不会持久化。

录音期间显示“正在接收指令”，没有实时转写。取消或60秒未结束会丢弃本轮，
不上传、不提交。转写为空或超过500字同样不提交，并回到等待唤醒。
模型故障、处理积压、ASR服务异常或麦克风断开会关闭监听并说明原因，需重新开启；
不会自动退回持续上传方案。关闭后的迟到识别结果不能执行动作。

助手生成、播放回答或地球仪播放讲解期间暂停收音，不向检测器送音频。播放结束后
等待1.2秒，重新开启麦克风并接入原来的Worker，减少扬声器尾音影响；不重新下载
权重或初始化模型。每次接通会重置小型识别流、音频时钟及本轮缓冲，并隔离旧轮次
迟到的检测结果。关闭监听、切换模型、切换课堂、
结束课堂、切换输入方式或离开页面都会关闭监听并丢弃未提交内容。
检测输入开启后，切换窗口或进入后台保持本地监听、已加载模型及本轮录音，回到
前台不重新加载模型或申请麦克风。是否暂停收音由助手回应状态控制，与窗口焦点
无关。按键输入进入后台仍取消本轮。页面刷新、离开页面或关闭页面会释放资源。
一轮指令完成或回答请求失败不关闭唤醒开关；失败会显示提示，不重发旧指令。
语音唤醒不支持打断助手播音，可使用“中断讲解”按钮。这里的关键词模型使用
CPU/WASM和系统内存，不占用LAM的GPU显存；只有关闭监听或退出相关页面时才卸载。

## 安装与运行

在项目根目录执行 `pnpm kws:setup`。脚本从上游固定版本地址下载运行时和模型，
验证压缩包及每个运行文件的 SHA-256，放入教师端 `public/vendor/local-kws/`。
下载文件不纳入 Git，版本、来源和哈希保存在 `scripts/local-kws-assets.json`。
前端生产构建会检查文件完整性，Vite 将模型、运行时和许可证一并复制到构建目录。
`pnpm kws:check` 可单独校验；运行时仅请求同源静态模型文件，不访问外部模型站点。
原始KWS模型与运行时约28MB，另包含约629KB的Silero VAD和许可证；首次加载后
浏览器可按静态资源缓存规则缓存。VAD包装脚本隔离作用域，避免覆盖KWS的内存清理函数。

个人模型需另运行 `pnpm kws:personal:setup`，默认从
`output/kws-personal-training-20260909/model/` 安装至
`public/vendor/local-kws/personal-20260909/`。也可执行
`node scripts/setup-personal-kws.mjs --source <FP32模型目录>` 从备份恢复。
四个模型文件的固定SHA-256保存在 `scripts/personal-kws-assets.json`；
`pnpm kws:personal:check` 和生产构建会校验它们，Vite将其一并复制到部署目录。
微调版同时常驻个人关键词权重和用于短“谢谢”的通用权重，运行时与VAD共用，
每轮不重复加载。原始录音及Torch训练
检查点不会复制到网页。新的机器需要提供上述个人模型文件，不能从上游下载代替。

“小麦老师微调模型（第10轮）”是独立的第三个选项，ID 为
`xiaomai-20260909-epoch10`。运行 `pnpm kws:xiaomai:setup`，从
`output/kws-xiaomai-extended20-20260909/epochs/epoch-10/model/` 安装 FP32 ONNX；
备份恢复可用 `node scripts/setup-personal-kws.mjs --model xiaomai-20260909-epoch10 --source <模型目录>`。
`scripts/xiaomai-kws-assets.json` 固定第10轮检查点及四个文件的 SHA-256，
`pnpm kws:xiaomai:check` 和生产构建均检查资产完整性。
该选项的唤醒、长结束词、短“谢谢”和取消图全部使用第10轮权重，与候选评测路由一致。
原始模型仍为首次使用的默认选项，原有个人版保留；关闭监听后切换，选择会保存在本机。
第10轮来自四词小样本训练，并不表示课堂识别准确率优于原版；历史评测见上述训练报告。
接入时模型选择与资产校验通过，三种选项的33项直接KWS/VAD回放通过。
但第10轮在AudioWorklet连续对话回放中，短“谢谢”仍出现漏检：首次检查漏掉续说后的第二次
“谢谢”，单独复测也出现未进入待结束状态。因此该版本供实测比较，不能将其记为完整界面
回归通过；“非常感谢”回放通过。接入证据保存在 `output/kws-epoch10-frontend-20260909/`。

平台 ASR 仍需要 `DASHSCOPE_API_KEY`，可通过 `EDU_SELFSTUDY_ASR_MODEL` 配置
识别模型。当前默认 `qwen3-asr-flash-2026-02-10`。`speech.asr` 为 true 才允许开启
完整语音指令流程。唤醒/结束检测本身不需要互联网，完整指令转写和助手回答仍
依赖现有服务。ASR 保留教师身份、同源与配额边界，每个完成的录音只识别一次。

使用支持 WebAssembly SIMD、Worker、AudioWorklet 的 Edge/Chrome，并通过 HTTPS
或 localhost 访问。学生课下入口保持原有输入方式。
最终课堂动作仍使用原有白名单与教师权限，不增加自动发布或自动推进行为。

## 灵敏度调整（2026-09-08）

唤醒词单独设置声学阈值0.12（原0.25）、关键词加分1.8；新增“你好助手／你好小助手”，并保留原口令。结束词“谢谢助教／谢谢澜舟”阈值0.15、加分2.5，“非常感谢”阈值0.2、加分2.0。候选路径数由4增至8，以减少候选过早被丢弃。取消词使用阈值0.15、加分2.5，避免在结束词增强后被压制。
唤醒短语要求整词不超过3秒。主口令“你好助手”的相邻音素识别时间戳间隔不超过1.0秒（2026-09-09由0.6秒放宽），容许自然的词间停顿；其他唤醒口令仍为0.6秒。全部口令统一放宽的回放实验出现了跨句误识别为“你好小助手”的情况，因此仅放宽有个人录音验证的主口令。识别时间戳间隔包含音素时长，并不等于真实静音时长；请自然说出唤醒短语，唤醒后可以停顿再说指令。最终仍需用教师的实际声音验证。
结束词还检查连续性：整词不超过2.4秒、相邻音素间隔不超过0.6秒，防止把“非常感慨……谢谢大家”跨停顿拼成“非常感谢”。请自然连贯说出口令。

降低阈值会提高触发灵敏度，也可能提高误唤醒率。受控音频回放用于对比，不等于真实课堂召回率。`scripts/verify-keyword-acoustics.mjs` 使用不同速度、音量和噪声条件进行本地模型回放；实际声学测试报告在 `output/voice-wake-review/`。

唤醒与结束/取消使用独立的关键词图，待机只运行唤醒检测，录音时只运行结束/取消检测，防止高灵敏度的结束词抢占唤醒候选路径。阶段切换时清理上一阶段的识别上下文，以静音预热新检测流，避免唤醒尾音与后面的“助教取消”误拼成结束词。音频录制仍保留短暂唤醒上下文；超时则切回唤醒检测。

取消词也使用独立检测图，在录音阶段与结束词检测并行；取消优先。结束词命中后最多等待1秒确认，给“助教取消”的后半句完成检测的机会，避免高灵敏度结束词抢先提交。未确认的结束候选不会触发ASR。

## 小麦老师与短结束词（2026-09-09）

“小麦老师”使用声调拼音 `x iǎo m ài l ǎo sh ī`，与其他称呼一样只存在于待机图。
短“谢谢”单独使用通用权重的检测图，避免压制长结束词和取消词。检测需有近期VAD
人声，并检查音素时长与间隔；允许快速发音和关键词解码延迟。恢复说话取消待结束
后，2秒内过短的重复对齐被抑制，避免旧“谢谢”的残留结果在后续停顿时重新触发。
控制词图也识别完整的“谢谢大家”：只撤销待结束状态，保留本轮录音，补偿短词
解码延迟导致VAD未及时观察到后续“大家”的情况。
VAD使用512采样点窗口，讲话/静音最短判定均为64ms；待结束状态累计1秒VAD静音，
