# 作业答辩

入口为教师及学生导航中的「作业答辩」（`/defenses`）；教师课程工作区也有本课程入口。

## 使用流程

1. 任课教师选择课程，填写作业要求、参考答案及能力维度。界面默认提供思路解释、概念理解、检验纠错、迁移应用，可修改名称、要求和权重。权重合计100%，题数4–8。API支持2–6个维度及3–8题，但题数须覆盖所有维度。
2. 保存草稿、检查后发布。本课程学生可见作业要求及评分维度，参考答案仅教师可见。发布后要求锁定；要更换题目，请新建作业。截止时间或「停止收取」仅限制新的解答提交，不中断已提交学生的答辩。
3. 学生粘贴解答文字、计算过程或代码，可说明工具与AI使用情况。提交即锁定原文。当前版本不解析PDF、图片、音视频等附件，请将关键图表数据转写为文字。
4. 学生点击开始，每次回答一题，再主动获取下一题。模型围绕当前能力维度，引用解答或上一回答，追问思路、条件、检验或迁移。最后一题回答后点击「完成答辩」。草稿保存在当前标签页的sessionStorage，已提交记录保存在服务器；答辩需要联网。
5. 教师查看原文与逐题记录，可在当前题已回答后追加现场追问（总计最多12题）。学生页面每10秒同步，也可手动刷新。已完成记录追加追问后恢复为答辩中；已复核记录不再追加。
6. 教师按每维度0–4级评分，并填写证据和综合反馈；总分为 `sum(等级 / 4 × 权重)`，保留一位小数。可先保存私人评价，再明确公布给学生。教师可导出包含原文、全部问题、回答和评价的JSON记录。

## 能力证据与模型边界

这个模块不进行AI文本检测，也不自动认定作弊。学生是否能独立解释、检验、纠错和迁移，需结合答辩记录与教师判断。重要考核宜结合监考或现场追问。文字答辩不能保证远程学生没有使用外部协助；当前不包含语音面试、摄像监考、身份核验或限时考试。

复用服务器现有 `OpenAiCompatibleAssistantProvider` 及模型配置。生成请求将题目、维度、教师参考要点、学生解答、工具说明及最近两轮记录发送给配置的模型提供商。服务器将这些内容标为不可信待考察材料；模型输出必须通过结构校验，追问的anchor须逐字存在于原解答或上一回答，辅助评分须有可核对的回答引文。校验不能替代教师审题。

提供商不可用、响应不合法、引用不匹配或30秒超时时，改用明确标示的「规则追问」，无自动分数。AI辅助评价只供教师查看，不直接进入正式成绩；未公布的教师评价、参考答案和其他学生记录均在服务端隔离。

校园模式复用AI并发、排队和每日额度限制。普通学生助教开关 `EDU_STUDENT_AI_ENABLED` 仍仅控制已有问答、ASR与TTS；答辩属于独立考核入口，不受该辅导开关影响。额度用完或排队失败时保留当前答辩，允许稍后继续；这些情况不会写入伪造的模型结果。

## 存储、权限与恢复

新增数据库 `${EDU_DATA_FILE}.defense.sqlite`，开启WAL和FULL同步。作业、解答快照、逐题回答、评价与请求回执独立保存，不修改课程课件和现有实验成绩。现有停服备份工具遍历同目录的 `.sqlite`，会包含此数据库；恢复应保留整套数据库。

仅课程所属教师可创建、管理和复核答辩。学生选课范围、身份、记录所有权在服务端检查；模型调用返回后重新核对身份和选课范围。单个答辩同一时刻只生成一个追问，所有写入有版本冲突检查；回答重试用请求回执去重。已提交原文不可改写，刷新、重新登录或服务重启后可继续同一份答辩。
