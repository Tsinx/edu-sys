# 港口仿真 V0.05 情境挑战与可解释排行榜说明

## 1. 版本目标

V0.05 将 V0.04 的可靠多人运行底座升级为可直接实施的课堂挑战。用户可见版本为 `V0.05`，业务规则仍使用场景 `0.0.3`；案例内容单独使用版本 `1.0.0`，因此修改任务简报、观察问题或计分解释时不需要伪装成设备规则升级。

排行榜用于激发团队竞争，但正式成绩仍必须来自服务端确认的权威业务状态。SVG位置、浏览器动画、网络延迟、事件重发和界面点击次数均不得直接产生分数。

## 2. 内置挑战案例

| 案例 | 难度 | 主要冲突 | 事件条件 |
| --- | --- | --- | --- |
| 第一次联合值班 | 入门 | 四岗位完成第一条完整作业链 | 无额外故障 |
| 稀缺岸桥的选择 | 进阶 | 大伸距岸桥、泊位和轨位联合匹配 | 教学船B提前到港，无额外故障 |
| 故障与高峰叠加 | 挑战 | 故障后瓶颈转移与陆侧高峰 | 04:30 AGV-03故障；06:00外集卡集中到达 |

三个案例都使用相同的原创教学港、双船任务和安全规则。案例差异由版本化案例定义和确定性场景投影产生，同一案例版本、初始状态和命令序列必须得到相同结果。

## 3. 1000分计分结构

| 维度 | 满分 | 权威依据 |
| --- | ---: | --- |
| 安全规范 | 250 | 被安全或前置条件拦截的命令、岸桥匹配拦截 |
| 任务完成 | 250 | 已完成教学批次占全部批次的比例 |
| 船舶周转 | 200 | 锚地、航道、泊位和装卸阻塞累计等待 |
| 资源协同 | 150 | 设备阻塞、岸桥移动距离和匹配阻塞 |
| 故障恢复 | 100 | 已发生事件从开始到恢复所占用的时间窗口 |
| 岗位协作 | 50 | 四个主操岗位是否都完成至少一次有效决策；不按命令数量加分 |

计分公式由共享核心包执行，服务端课堂汇总和浏览器本组展示调用同一函数。每个维度包含说明和最多六个相关事件 ID。分值允许实时变化，仿真结束后标记为最终成绩。

教师接管会将该轮标记为 `practice`：仍展示分数、事件和复盘，但 `rankEligible=false`。这样既允许教师救场，也不会让人工接管改变正式竞赛名次。

## 4. 三类榜单

- **课堂总榜**：开局后，所有未发生教师接管的小组按总分排序；准备阶段不提前产生名次。
- **同编制榜**：4人、5人、6人小组分别排序，避免协作席数量差异被隐藏。
- **进步榜**：第二轮开始，将当前成绩与该组此前最佳正式成绩比较；第一轮没有进步名次。

同分时依次比较安全得分、完成批次数、总等待时间，最后按稳定的小组 ID 排序。跨组公开信息只有组名、编制、分数、任务进度、安全拦截和主要等待；其他组学生姓名不会进入榜单。

## 5. 课堂使用流程

1. 教师在建组前选择挑战案例，案例在开局后锁定。
2. 学生进入小组后查看公开情境、团队任务和本岗位简报。
3. 开局前榜单显示等待提示；运行中显示暂定成绩，点击计分维度可查看相关权威事件。
4. 教师结束本轮后成绩封存；如有教师接管，该组显示为练习成绩。
5. 教师重置进入下一轮，系统保留上一轮正式成绩作为进步基线。

V0.05 不提供个人排行榜，不奖励命令数量或设备表面利用率，也不自动给出最优调度方案。排行榜服务于团队协作和因果复盘，不替代学生解释决策。

## 6. 数据与同步边界

- `challengeId`、`challengeVersion`、轮次和历史最佳成绩进入检查点与小组快照。
- Worker依据检查点中的案例 ID 选择相同确定性场景进行回放。
- 排行榜汇总由服务端从每组权威引擎状态计算；客户端不得提交分数。
- 重置后客户端强制读取新检查点，确保轮次和进步基线同步。
- 旧 V0.04 运行缺少案例字段时按“故障与高峰叠加”兼容，不改变原业务状态。

所有船名、任务、计分权重和事件参数均为教学设计，不代表真实码头绩效考核或实装配置。
