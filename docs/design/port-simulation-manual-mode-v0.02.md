# 港口仿真 V0.02 纯手动协同运行说明

## 1. 版本目标

V0.02把可浏览的SVG港区总图升级为课堂可运行的协同仿真。系统维护唯一权威业务状态并执行已经批准的物理动作，但不替学生完成任何管理与调度决策。

“纯手动”不要求学生逐帧驾驶船舶或设备。它要求进出港次序、引航拖轮、泊位岸桥、AGV、堆场和闸口等资源配置都由学生岗位明确下令。无人下令时，时钟继续推进，对象继续等待，相应延误持续累积。

## 2. 场景范围

### 2.1 两级空间语义

- 港口总体层：港界、港口水域、港口陆域、锚地、进港航道、回旋水域、港外航线入口和腹地集疏运接口。
- 码头作业层：7个泊位、岸桥作业区、AGV通道、自动化堆场、外集卡通道、闸口、生产控制中心、维护充电区。

### 2.2 固定教学条件

| 条目 | 固定条件 |
| --- | --- |
| 场景 | 双船全流程纯手动协同，版本 `0.0.2` |
| 时长 | 720个仿真分钟 |
| 船舶 | 教学船A“海岚”、教学船B“江澄”，到港时段重叠 |
| 任务 | 每船4个卸船批次和4个装船批次；批次不是TEU |
| 海事资源 | 1组引航、2艘拖轮、1条受控主航道 |
| 码头资源 | 7个泊位、6台岸桥、4台AGV、24个堆场块、2条闸口通道 |
| 固定事件 | 04:30时AGV-03故障60分钟；06:00时外集卡集中到达 |
| 倍速 | 教师统一控制0.5×、1×、2×；1×时每现实秒推进1个仿真分钟 |

两艘船、任务、时刻和资源配置均为虚构教学条件。场景不映射真实港口的实时生产状态。

## 3. 四岗位分工

| 岗位 | 可执行决策 | 主要依赖 |
| --- | --- | --- |
| 港调 / VTS | 配置引航与拖轮、批准进港或离港 | 泊位已经分配、航道空闲、装卸已经完成 |
| 泊位与岸桥 | 分配泊位、配置岸桥、开始装卸、释放泊位 | 船舶阶段、泊位兼容、岸桥与AGV配置 |
| 水平运输 | 分配AGV、设置船舶运输优先级、安排空闲AGV充电 | AGV可用性、故障状态、堆场准备情况 |
| 堆场与闸口 | 为批次分配堆场块、办理批次陆侧放行、开闭闸口通道 | 堆场容量、批次阶段、闸口排队压力 |

组内所有成员共享港口态势。每个岗位只有一名主操，其他成员为观察者；同一学生不能同时占用多个岗位。

## 4. 状态推进与命令规则

### 4.1 权威状态

权威状态只由两类输入改变：

1. 通过岗位权限和业务规则校验的人工命令。
2. 仿真时钟触发的确定性业务事件，例如船舶到港、航行完成、装卸进度、AGV故障与恢复、外集卡到达。

SVG位置和动画只是业务状态的视觉投影。`requestAnimationFrame`、页面可见性和减少动态效果设置不会改变权威时钟；只有教师的全局暂停能够暂停业务推进。

### 4.2 安全硬约束

至少执行以下拦截：

- 航道同一时刻只能由一艘受控船舶使用。
- 泊位必须与船型兼容且没有被其他船舶占用。
- 船舶获得泊位后，才能配置进港所需的引航与两艘拖轮。
- 船舶靠妥后才能开始岸桥作业。
- 同一设备不能同时分配给两个对象。
- 批次必须有可用堆场容量。
- 全部装卸任务完成后，船舶才能离泊和离港。
- 岗位只能提交本岗位命令。

被拒绝的命令返回原因码、面向学生的说明和最新状态版本，并写入事件日志。

### 4.3 允许低效决策

下列决策只要安全就会执行，不由系统替学生优化：

- 选择运输距离更远的兼容泊位或堆场块。
- 为船舶配置较少的岸桥或AGV。
- 过早充电、关闭闸口通道或设置不理想的优先级。
- 让资源空闲、让船舶等待，或在固定事件发生后响应迟缓。

这些后果通过锚地等待、航道等待、泊位等待、设备忙闲、阻塞和闸口队列呈现，不折算为虚构吞吐率。

## 5. 多小组课堂运行

### 5.1 教师流程

1. 建立1至12个独立小组并设置显示名称。
2. 学生自行选择小组和认领岗位。
3. 默认等待参与比较的小组四岗就绪；教师可明确确认带缺岗开局。
4. 同步开始全部小组，并统一暂停、继续或切换倍速。
5. 必要时释放失效岗位，或以教师人工接管方式提交单组命令。
6. 结束后并列查看各组诊断复盘；不生成排名。

带缺岗开局和教师接管都会记录在复盘事件中。教师接管仍是人工命令，不构成自动托管。

### 5.2 状态隔离与并发

- 每个小组拥有独立的引擎状态、修订版本、命令回执和快照流。
- 学生命令携带幂等请求ID、岗位凭证和预期版本。
- 重复请求返回已有结果且不重复执行；过期版本返回冲突和最新快照。
- 服务端串行验证命令；任一小组的命令不得改变其他小组。
- 正常更新使用SSE；断线时客户端每5秒轮询快照。
- 岗位断线保留45秒，同一终端可凭本地岗位令牌恢复；到期后可以重新认领。
- API重启后，运行中的小组转为“因服务重启暂停”，由教师确认恢复。

## 6. 复盘口径

复盘只用于识别因果和比较策略，不提供总分、排行榜或虚构实时吞吐率。

- 船舶：锚地等待、航道等待、泊位等待、装卸时间和在港时间。
- 资源：岸桥、AGV、堆场、闸口的忙碌、空闲、阻塞和排队变化。
- 岗位：响应时间、命令时间线、安全拦截和教师接管记录。
- 事件：AGV故障和外集卡集中到达后的恢复过程与主要延误来源。
- 课堂：各组并列展示相同初始条件下形成的不同运行结果，不计算排名。

## 7. 公开与技术边界

功能结构参考上海洋山四期自动化码头公开资料；所有图形为原创教学示意，非工程图、非导航图。V0.02不使用真实地理坐标、工程参数、实时港口数据、实名花名册、内置聊天、AI调度、自动优化、正式评分、单箱级仿真或第三方运行插件。

运行内核位于 `@edu/port-simulation-core`，保持无UI、无I/O和确定性；Teacher Web负责命令面板与SVG投影，Platform API负责小组隔离、岗位凭证、命令串行化、持久化和快照分发。
