# 港口仿真 V1.0 登录后本地单机运行说明

## 1. 决策与目标

V1.0 将默认课堂模式从联网小组协同改为登录后本地单机运行。原因是课堂网络、长连接稳定性和服务器容量都不应成为学生完成实验的前置条件，同时每名学生都需要亲自经历港调/VTS、泊位与岸桥、水平运输、堆场与闸口四个业务岗位。

软件版本写作 `V1.0`，本地存档格式为 `1.0`，应用存档版本为 `1.0.0`。确定性业务场景仍为 `0.0.3`，三个挑战案例仍为 `1.0.0`；交付方式变化不伪装成港口设备规则变化。

## 2. 运行边界

进入过程分成两段：

1. 浏览器向平台读取登录身份和课堂挑战配置。
2. 页面载入完成后，由浏览器本地确定性核心独立推进全部业务状态。

第二阶段不需要以下网络能力：

- 小组加入与岗位认领；
- SSE事件流、检查点补取和轮询降级；
- 岗位租约、在线心跳和断线重连；
- 服务端仿真时钟与命令裁决；
- 实时排行榜和教师接管。

教师发布 `deliveryMode: local_solo` 时，Platform API 只保存挑战 ID、版本、预计登录人数和课堂活动状态，`teams` 固定为空。服务器不会为70名学生创建70套运行状态，也不会按秒推进状态。

## 3. 学生全流程体验

学生在同一画面切换四个岗位。岗位切换不暂停已经批准的机械动作，也不清除其他岗位的决策：

| 岗位 | 学生承担的核心决策 |
| --- | --- |
| 港调/VTS | 到港顺序、锚地等待、引航拖轮、进出港航道 |
| 泊位与岸桥 | 泊位选择、岸桥轨位移动、伸距匹配、装卸开工 |
| 水平运输 | AGV分配、运输优先级、充电与故障后的重新配置 |
| 堆场与闸口 | 堆场批次、闸口通道、外集卡到达压力 |

系统仍只自动执行已经批准的航行、移位、装卸和运输等物理动作，不自动替学生作出管理决策。安全硬约束继续拒绝不合法命令，低效但安全的选择继续形成真实等待和阻塞。

## 4. 本地存档与恢复

每个登录身份、课程和挑战使用独立的浏览器存储命名空间。存档包含：

- 应用、挑战和场景版本；
- 当前轮次、当前岗位和本地运行 ID；
- 完整确定性引擎状态与事件记录；
- 最近保存时间。

读取存档时使用共享契约校验引擎状态，并核对挑战、场景 ID 和版本。损坏、跨版本或跨场景存档不会被执行，而是恢复该案例的初始状态。

浏览器关闭时若状态仍为 `running`，下次进入会恢复为 `paused`。页面进入后台时也会先推进到当前时刻再自动暂停，防止后台节流造成无人决策的意外延误。

当前浏览器最多保留30轮个人完成记录，并显示最近5轮。导出的复盘 JSON 包含挑战、计分、引擎状态和事件证据，不包含姓名、内部 actorId、外部学号或身份令牌。

## 5. 计分与可信边界

V0.05 的六维1000分解释框架继续用于个人诊断和自我比较。V1.0 不提供联网排行榜，也不把浏览器本地分数认定为服务器认证成绩。学生可以使用开发者工具修改本地数据，因此正式考核若未来需要可信成绩，必须另行设计“显式提交最终事件包、服务端确定性复算”的低频接口。

本版不会为恢复排行榜而偷偷持续上传命令、快照或心跳。

## 6. 兼容策略

- `network_teams_legacy`、SSE Worker、SQLite事件仓储和旧教师/学生多人组件暂时保留，以便读取或复核 V0.02–V0.05 历史运行。
- 新教师入口只发布本地挑战；新学生入口只实例化本地运行器。
- 遇到旧课堂多人配置时，学生入口读取其挑战 ID 作为本地个人副本，不重新连接旧小组。
- 独立预览保留 V0.05 协同兼容标签页，但默认展示 V1.0 本地单机。

## 7. 不在 V1.0 实现

- 联网小组协同、实时排行榜和教师远程接管；
- 本地成绩自动上传、后台遥测或远程监考；
- 跨设备云同步、浏览器间迁移和服务端存档；
- 花名册固定分组、自由聊天和AI自动调度；
- 真实港口工程参数、实时生产数据或导航用途。
