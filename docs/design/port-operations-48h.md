# 48 小时港口综合实训

本版本在现有 Three.js 港区上增加独立的 `port-operations/3.0` 业务内核。默认入口为综合实训，页面底部可进入 8 小时基础实训；原 `terminal-lab/2.0`、`2.1` 和 `terminal-training/1.0` 仍由原内核解释，不补算新成绩。

## 使用方式

生产预览：<http://127.0.0.1:4173/port-simulation-preview.html>。

1. 在“规划”中选择教学或实战模式，设置到港参数、设备型号、数量、堆场用途和位置。位置交换有拖拽和下拉框两种入口，至少保留一个待核查区。在“调度”中配置岗位和泊位岸桥。
2. 阅读开局评分规则。船期仅公开未来六小时；可先预约泊位、分配已公布货批的堆场。预约条是预测，不取得实际泊位占用权。
3. 开始值班后核对船舶航前资料与预填申请，提交进口岸、检疫、边检和出口岸准备。教学反馈时间为 10 分钟；货批资料核验为 15 分钟。这些时长属于情境假设，不是实际审批时限。
4. 船舶实际到达后，可拖至泊位或港内候泊锚位，也可使用船舶操作中的目的位置选择。系统同时检查通行资源、适配性、手续和目的位置，并原子预留。
5. 靠妥后组织装卸。货批可以拖到主场景下方堆场目标，或通过下拉框分配。进口卸船与后续监管放行分别判断；出口资料、陆侧集港、堆场提箱和装船构成独立链条。
6. 点击箱号查看实际交接账本。封志异常按箱独立送检；整票单证条件对关联的全部箱生效，没有拆分界面批次以绕过限制的入口。已入场货批重新分配时，系统执行真实移箱，计入场桥、运输时间和费用。
7. 本港装卸完成、出口岸准备办妥且航道可用后离泊出港。进口提离不占用已释放泊位，仍受自身承诺期限约束。
8. 48 小时结束后核对交班、责任岗位和下一步安排。从已完成实战中选择最终结果并导出；“提交教师”明确显示尚未联网。

窄屏、键盘选择、菜单、HTML 拖拽和三维船舶拖拽都形成相同的业务命令。普通现场消息不抢夺对象焦点，也不自动选择调度方案。

## 生成器与时间

生成器版本为 `port-arrivals/1.0`，默认种子 `20260932`。在开局前确定全部挂靠、货量、资料偏差及 ETA 更新。到港、货量、ETA 偏差、船型和资料使用分离的随机流，查看档案和重复点击不消耗随机数。

- 首船首报 ETA 为开局后 60 分钟，开局显示第 1 天 08:00。
- 工作量为三角分布 `Triangular(72,168,264)`，进口约 60%，出口约 40%；每船两个进口和两个出口批次。
- 参考服务时间为 `30 + Q × 1.25` 分钟，理论均值 240 分钟。它仅供预计与承诺计算，不触发离港。
- 名义间隔为 `15 + Gamma(k,(平均间隔−15)/k)` 分钟。低、中、高波动分别取 `k=4,2,1`。配置要求平均间隔大于 240 分钟。
- ETA 偏差取 `Triangular(-45,0,90)` 分钟，在首报 ETA 前三小时和前一小时逐步更新；已经在开局前发生的更新于开局反映。首报 ETA 始终保留。
- 生成延伸至第 54 小时；首次进入六小时窗口时公开，延期不会撤销已经公布的任务。学生投影中不含尚未公布挂靠、未来实际到港时间和潜在异常字段。
- 实际到达港界、抵达泊位及系泊完成分别记录。港口时间点的区分参考 [IMO 港口时间与信息协调框架](https://greenvoyage2050.imo.org/pdf/just-in-time-portal/)。实现中的尺寸、工作率、许可条件和费用均为教学简化。

教学模式首次遇到新的流程种类时准确暂停；处理当前情况后可继续等待。同类业务不重复暂停。实战固定 60×，每 500 毫秒按真实经过时间向工作线程提交推进量；后台节流后补算经过时间。切换同场次工作台面板不停止业务。教学模式切到后台自动暂停。

所有箱级任务使用离散事件完成。事件固定排序，资源变更保留已做工作量。成本从整数设备秒、人员秒和投入秒积分计算，避免浏览器不同分帧方式引起重放浮点累加漂移。

## 空间与资源

两个泊位、四个港内候泊锚位、一个抽象港外等待区共用单向通行资源。目标预留在进入通行任务前取得；港内候泊船开始离开原锚位时释放锚位，船舶离开泊位后释放泊位。无可用目的位置时，船保留原位置，不在航道上停车。

六个堆场各 100 箱，实际占用和运输入场预留共同限制容量。装卸岸侧有有限缓存，场桥、车辆和闸口会受到岗位数量、设备选型、距离和供能的共同限制。船型同时受到泊位适配和岸桥伸距限制。用于展示的三维动画投影业务任务的进度，不决定任务是否完成。

每八小时自动轮换班组，箱位、在制任务、手续和异常连续保留。教学抽象管理岗位和班组，不维护个人考勤。最终交班包含库存、未完船舶、货批、异常箱及故障设备；逾期履约不会因交班被重置。

## 本地评分

| 分项 | 计算 |
|---|---|
| 货物履约 50 分 | 在评价时点已到承诺期限的箱中，按时进口提离或出口装船的比例 |
| 船舶流程 20 分 | 在评价时点应完成船舶的进港、靠妥、实际开工、离港节点完成比例 |
| 经营效率 20 分 | 到期任务已完成比例 × `min(1,参考单位成本/实际单位成本)`；没有完成货量不得分 |
| 交班完整 10 分 | 完整核对当前库存与未完事项的责任岗位和下一步安排 |

承诺在实际到达后固定：船舶周转和出口装船为实际到达＋参考服务＋4 小时，进口提离再加 2 小时。到港前显示的是随 ETA 更新的预测。普通延误没有独立的额外超时罚分。

明确违反流程前置条件，实战对同一业务对象、同一种错误扣 5 分一次；教学只记录解释。资源阻塞、泊位不适配、表单补正、重复或过期操作不扣分。所有拒绝和等待都有结构化判定与原始状态，复盘保留扣分依据。

参考单位成本由同一情境的固定基准方案完整运行得到：正确处理资料，先到先服务，兼容泊位优先，优先安排有余量的近侧堆场，维修和异常及时接续。基准不是最优方案，也不保证其所有货物按时完成。参考计算在独立工作线程执行，计算完成前不显示虚构效率分。中断场次只提供进度与诊断，不可选作最终成绩。

## 文件与接口边界

核心模块位于 `packages/port-simulation-core/src/port-operations-*.ts`：

- `model`：版本、配置、确定性生成器和实体模型。
- `engine`：业务命令、资源预留、箱级任务、许可反馈、异常及交班。
- `review`：固定参考方案、评分、存档导入导出和重放。
- `view`：经筛选的学生展示数据。

网页位于 `apps/teacher-web/src/features/port-simulation/PortOperations*`、`usePortOperations.ts` 和 `port-operations.worker.ts`。Three.js 保留静态港区，按 ID 更新动态船舶和实例化集装箱；船舶到达及箱量变化不会重建整个场景。

`TerminalStudio` 默认接入新实训；`LegacyTerminalStudio` 保留基础训练。课堂继续使用已有 `trainingMode: practice | battle` 配置，学生载入后锁定教师模式；既有挑战 ID 映射为综合值班、集中到港规划和故障持续运营。

存档按身份/课程 scope、场次类型和版本隔离。每次挑战独立保存，刷新或离开后的未完实战按中断恢复。导入从参数、种子、生成器版本、初始方案和命令重新生成情境并执行，不信任文件内附带成绩。导出包含完整交接账本、场次与船期、资料反馈、原始状态、指令、判定、成本与评分，不包含姓名、学号、账号 ID 或身份令牌。

本期综合实训存档不会进入既有 `/api/edge/records` 同步队列。“提交教师”是明确禁用的本地占位，未发送成绩请求，也不显示提交成功。

未来服务器接口建议（本期未实现）：

| 接口 | 作用与最小内容 |
|---|---|
| `POST /api/port-operations/sessions` | 教师配置场次：课程引用、允许模式、生成器版本、参数、种子策略、起始方案约束 |
| `POST /api/port-operations/submissions` | 身份由授权会话绑定；提交去身份化的参数、种子、版本、初始方案、完整命令与幂等提交 ID |
| `GET /api/port-operations/submissions/:id` | 返回接收/复算/拒绝状态，服务端复算评分和规则依据；不得直接采纳客户端附带分数 |
| `GET /api/port-operations/courses/:id/results` | 教师权限下的场次汇总、已选最终结果、履约与过程诊断 |

服务端将需要确认版本、教师限制、时钟连续性、完成状态和导出完整性；本地练习存档本身不构成可信在线考试凭证。
