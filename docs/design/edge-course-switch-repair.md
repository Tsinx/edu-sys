# 港口课堂切换白屏修复

2026-10-14，本地 Edge 原标签页核验。

## 原因

Edge 控制台记录 `ClassroomSubsystem` 读取 `null.localIndex`，React 根节点被清空。运行中的 API 仍返回 v15 港口课件（581 页）的第 550 页、`l12-dangerous-cargo`；前端已使用 v20（549 页）。快速切回旧课堂暴露了版本与页码不一致，实际不是地图或影片加载失败。

## 修复

- 课堂直接从当前快照的课程标识取得注册表，移除另一份异步注册表状态；切换课堂时不渲染前一个课堂快照。
- 教师与学生入口都核对课程、课件标识、版本、页面标识、全局页码和讲次。无法对应时提供可恢复提示与重新加载、返回课程入口，保留原记录。
- 服务重新加载时，旧港口页仍存在则按稳定标识恢复；已删除页按 `l11-`、`l12-` 等标识恢复到原讲首页，不套用早期三讲课程的数字映射。已结束课堂的持久化原记录保持不变。
- 备份原状态后，通过现有启动脚本重启本地 API。实际课堂已返回 v20、第 12 讲首页（全局 518 / 549）。

## 验证

- 真实 Edge：更新前的旧快照会出现恢复提示；更新后第 11 / 12 讲连续切换 8 次，课程—课堂—工作台往返 5 轮，刷新恢复通过。
- 最终停留用户报告的 `/courses/course-port-management-intro`，12 讲目录正常，图片无损坏；调试日志没有新增页面异常。最初报错仍保留在历史控制台中。
- 前端测试 217 / 217；相关后端测试 18 / 18（含旧版本恢复、课程上下文与经济数学历史记录）。
- 教师前端与 API 类型检查通过，Vite 生产构建通过，本次涉及的已跟踪文件 `git diff --check` 通过。
- 日志与重启前状态备份保存在 `output/edge-course-switch-fix/`。未提交、推送或部署。
