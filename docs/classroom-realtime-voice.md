# 课堂实时语音

课堂助手的按键录音与唤醒录音仅使用**实时语音**，进入活动课堂后自动准备连接，不再提供链路选择。浏览器以前保存的旧路径偏好不再生效。文字输入和课下学习保持原有接口。

## 本地配置

在项目根目录 `.env` 设置以下字段，随后重启平台 API。使用 `start-classroom-https.bat` 打开 `https://localhost/`。

```dotenv
EDU_REALTIME_ENABLED=true
EDU_REALTIME_URL=wss://YOUR_WORKSPACE.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime
EDU_REALTIME_MODEL=qwen-audio-3.0-realtime-plus
EDU_REALTIME_VOICE=longanqian
# 可选独立密钥；留空时使用已有 DASHSCOPE_API_KEY。
EDU_REALTIME_API_KEY=
```

地址和密钥须属于可调用该模型的业务空间、地域。密钥只在平台 API 中使用。`/api/runtime/config` 仅暴露 `speech.realtime.available`。开关、地址或密钥缺失时，录音入口不可用并提示使用文字，不回退到独立 ASR。实时语音支持 Live2D 和浏览器视频形象；开发环境的 LAM 3D 形象暂不支持实时音频输入，需切换到上述形象后录音，也可继续文字输入。

旧 `/api/teacher/asr`、课堂 `/avatar/commands` 的 `inputMode=voice`、课堂 `/assistant/turns` 的 `source=voice_asr` 请求返回 HTTP 410 和 `CLASSROOM_REALTIME_REQUIRED`，不调用旧模型或执行动作。`/api/teacher/tts` 仍供文字回答和预置讲解朗读使用，自学语音接口保持不变。

## 数据流与行为

1. 浏览器复用本地 AudioWorklet 和关键词检测。按键或唤醒词开始后，以约 100ms 一块上传 16kHz、16bit、单声道 PCM；待机音频留在本地。结束词和按键控制提交，云端 VAD 关闭。
2. 平台通过同源 `/api/class-sessions/:id/assistant/realtime` WebSocket 连接实时模型，直接请求文字与语音。普通问答只生成一次响应，没有必经的静默分类。24kHz PCM 到达后立即进入浏览器播放队列；字幕流式显示，嘴型由输出音量驱动，不等待全文或 Rhubarb 分析。播放队列只留约30毫秒的调度余量，没有固定3秒等待。
3. 模型只有在需要课堂操作时才调用 `control_classroom`，一次调用包含1—8项动作。允许“好的，我来翻页”等普通确认语立即发声；工具参数使用独立事件，不进入字幕或音频播放队列。动作经现有契约、课程白名单和执行器校验，使用轮次 ID 去重。执行器在写入队列内再检查页面和提示词，避免旧指令作用于新页面。
4. 工具执行后，平台注入真实结果和当前页面，关闭工具，再请求语音确认或教学讲解。仅操作轮次需要这次额外响应。参数无效、未知工具或一次响应内出现多次调用时不执行动作；后续响应再申请工具也不会重复执行。已经播出的简短确认无法撤回，失败会在界面报告并停止待播音频，不自动重放。

角色、课程、讲次、页面和工具五层提示均由服务端复用编译。未揭示答案规则保持生效。最近六轮完整对话及实际操作结果作为带边界的历史参考注入；旧指令不能再次执行。页面或提示词变化时清除旧历史；取消、断线后创建干净会话。

`turn.completed.timing` 中，`responseCount` 是模型响应次数；`firstTextMs`、`firstAudioMs` 分别记录提交到服务端收到首段字幕、首块音频的时间，`toolDecisionMs` 仅操作轮次存在，表示提交到完整工具参数校验通过的时间。普通问答不再记录静默判断耗时。浏览器首音另外按音频时钟计量，包含初始静音与播放调度，不能与服务端首块音频混用。

连接在进入活动课堂时预热，空闲两分钟后释放上游，下次录音时恢复。切换形象、取消或离开课堂会停止本轮及待播音频；连接失败提示重试或文字输入，不会自动重放录音或动作。按键/唤醒的收音方式、60秒录音上限和播音后的回声等待沿用现有行为。

## 麦克风启动排查

麦克风属于**运行浏览器的设备**。实时路径已经在该设备采集音频、分块送到平台服务器。若通过远程桌面操作服务器上的浏览器，浏览器需要远程桌面的麦克风重定向；直接在自己的电脑上打开课堂 HTTPS 网页，则使用自己电脑的麦克风。服务器端关键词检测也需要客户端先成功取得音频，不能解决权限未授予或输入设备不可用。

启动按钮分别显示模型加载、实时连接、麦克风请求、音频处理器加载和音频启动。麦克风请求超过20秒、处理器加载超过15秒、音频启动超过10秒时停止本轮并显示具体原因；取消后才到达的授权结果会立即释放设备。麦克风错误还会尽可能显示当前网站权限状态。

- **尚未授权**：处理浏览器的麦克风权限提示，或在地址栏网站信息中允许麦克风。`http://localhost:5173` 与 `https://localhost` 是不同网站来源，需要分别授权。
- **已阻止**：检查该网站的麦克风权限及系统对浏览器的麦克风访问权限。
- **已允许仍无法启动**：检查浏览器选择的输入设备、设备占用和远程桌面重定向；可在运行浏览器的设备上先测试系统录音。
- **远程访问**：使用受信任的 HTTPS 域名。普通 HTTP 局域网 IP 不具备浏览器麦克风所需的安全上下文。本地 Caddy 调试配置只监听回环地址，不能直接当作另一台电脑的访问入口。
- **课堂已结束**：重新进入正在进行的课堂；已结束课堂的录音按钮保持禁用。

2026-09-15 在实际浏览器排查时，按键模式停在 `getUserMedia` 请求，Edge 显示该网站权限为“尚未授权”。此前使用测试音频和预授权浏览器的自动化验证不覆盖用户浏览器的首次权限提示。

WebSocket 自行校验来源、教师身份和活动课堂；校园模式每轮进入既有 AI 并发、超时、额度管理。新旧路径共享当前活动轮次，课堂结束或服务关闭会释放连接与额度。录音、密钥和完整提示词不进入运行日志。

## 验证与复现

- `pnpm --filter @edu/platform-api exec tsx --test test/realtime.test.ts`：真实本地 WebSocket 加模拟上游，覆盖单次响应直接发声、操作确认、工具 JSON 隔离、去重、越权、上下文变化、隐藏答案、六轮历史、取消和校园额度。
- `pnpm --filter @edu/teacher-web exec tsx --test test/realtime-voice.test.ts`：流式收音边界、待机不上传及 PCM 转换。
- `node scripts/benchmark-classroom-voice.mjs --probe`：真实云端问答、纯操作、操作并讲解。
- `node scripts/verify-classroom-realtime.mjs`：实际按键收音、WebSocket、字幕、音频播放及桌面/窄屏切换。
- `node scripts/verify-classroom-realtime-kws.mjs`：实际本地 KWS/AudioWorklet 与真实云端，验证待机不上传、唤醒、结束词、取消及释放麦克风。复用 `.runtime/kws` 中既有合成测试录音。
- 旧的双链路测速脚本仅留作历史复现参考，旧课堂语音接口已停用。当前开发验证页可手动使用缓存录音验证实时连接；本次按用户要求不再执行延迟测速。

浏览器脚本使用已安装的 Playwright，可通过 `EDU_PLAYWRIGHT_ENTRY` 指定其 Node 依赖入口。测速脚本默认将新结果写入 `output/realtime-direct-qa/`，复用 `output/realtime-voice-qa/` 中的既有录音，不覆盖历史两阶段测速。可通过 `EDU_VOICE_BENCHMARK_OUTPUT` 指定其他输出目录。

也可在 HTTPS 开发入口打开 `/dev/realtime-voice-benchmark.html`，点击按钮执行三种场景探针或十题三轮测速并下载 JSON。该页复用课堂的真实 WebSocket 客户端与播放队列，播放已缓存的测试录音，不需要麦克风权限；此页不进入生产构建。

测速口径是“提交结束到浏览器安排播放的首个非静音 PCM 样本”，不包含教师说话时长，也不是扬声器的声学实测。旧路径包含 ASR、完整回答生成和带嘴型分析的 TTS；新路径包含直接生成回复和音频传输。冷连接准备时间另记，不能与首音时间混为一项。统计报告同时列出成功率、中位数与 P95；失败轮次不得当作零延迟或静默丢弃。操作确认语的首音不等于动作执行完成，更不等于操作后讲解开始。

## 2026-09-15 直接响应验证（已按用户要求停止测速）

已完成28次真实问答，均成功且只有一次模型响应。已有样本的浏览器首音中位数为1.25秒，P95为1.58秒；原计划30次，剩余两次按用户要求未继续，不视为完整三轮实验。三场景探针另行验证了问答、翻页、翻页并讲解；操作均执行一次，允许简短确认，组合指令使用新页面内容。

API 82项、前端104项测试以及类型检查、生产构建通过。已停止测试连接和播放，测试课堂已结束。记录与测量边界见本地 [停止时的验证报告](../output/realtime-direct-qa/report.md)。

## 2026-09-15 历史两阶段实测

以下为取消静默判断之前的实现数据，不代表当前直接响应版本。

同一组十条港口概念录音，各路径重复三次，真实调用结果如下：

| 路径 | 成功 / 尝试 | 首音中位数 | 首音 P95 |
| --- | ---: | ---: | ---: |
| 现有语音 | 30 / 30 | 5.14 秒 | 6.97 秒 |
| 实时语音试用 | 30 / 30 | 2.82 秒 | 3.54 秒 |

本组中位数缩短 45.2%，包括约 1.17 秒的静默判断。实时路径首次连接组（3 次）的首音中位数为 2.95 秒，复用连接（27 次）为 2.78 秒。连接在录音前准备，此处均统计提交后的等待。

这是本地开发环境的顺序试验，并非隔离、随机交错的性能基准；期间有开发验证活动，且回答长度并不固定。原始数据、测量边界与失败实现的诊断记录见本地 [实测报告](../output/realtime-voice-qa/report.md)。不能把这个比例当作所有课堂场景的速度保证。
