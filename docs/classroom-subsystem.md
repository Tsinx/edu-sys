# 课堂教学子系统 v0.1

## 定位

课堂页不是教师门户中的一个普通内容页，而是独立的课堂运行时。路由
`/classroom/:sessionId` 位于门户 `Shell` 之外，进入后由课堂命令栏、教学活动舞台、
数字人助手坞和课次状态共同接管整个视口。

当前课程数据为“港口管理概论”，教师为重庆交通大学李行之老师。课堂可以从系统
首页“开始上课”或课堂列表“立即开课”进入，课次、当前页、活动类型和数字人模式
均由平台 API 持久化。

## 子系统组成

| 层 | 组件 | 职责 |
| --- | --- | --- |
| 课堂外壳 | `ClassroomSubsystem` | 装载课次快照、命令栏、活动切换、课堂控制、数字人面板和结束课堂流程 |
| 学生课堂 | `StudentClassroom` | 通过邀请链接加入，只读同步当前 Slide，并维护真实在线租约 |
| 教学画布 | `SlideViewport` | 将固定逻辑画布等比缩放到当前可用区域，绘制黑边 |
| Slide 内容 | `TeachingSlides` | 在 1600×1000 坐标系中渲染课程页、航次叙事条和原生矢量图，不参与网页式重排 |
| 活动舞台 | `ActivityStage` | 在同一固定画布中承载模拟实验、白板、视频与互动模块 |
| 教师指令 | `VoiceCommandComposer` | 提供手动按住收音、上滑取消、松开发送及文字输入 |
| 平台状态 | `JsonStateStore` | 保存课次、当前页、当前活动和运行版本，并按学生心跳实时计算在线人数 |
| 平台助手 | `ClassroomAssistantOrchestrator` | 构造课堂上下文、调用 JSON 流模型、增量提取对白并在完整校验后执行动作 |
| LAM 适配器 | `LamAvatarSurface` | 把录音送入 OpenAvatarChat ASR，把平台 `dialogue` 增量送入 TTS/LAM，并加载 Barbara WebGL 资源 |
| 共享契约 | `@edu/contracts` | 校验课堂快照、助手响应、SSE 事件、课堂动作和文字/录音指令 |

课堂主舞台的活动边界统一为：

- Slides
- 模拟实验
- 白板
- 视频
- 互动

活动切换不会离开课堂路由，后续自研模拟器可以作为受控模块挂载到
`ActivityStage`，继续复用课次、数字人、课堂控制与事件留痕。

## Slide 固定画布契约

逻辑画布固定为：

```text
宽度：1600
高度：1000
宽高比：16:10
适配方式：contain
空余区域：纯黑 letterbox
```

若设备提供的舞台区域为 `W × H`，统一缩放系数为：

```text
scale = min(W / 1600, H / 1000)
```

实际 Slide 始终渲染为：

```text
renderedWidth  = 1600 × scale
renderedHeight = 1000 × scale
```

画布中的标题、字号、图形和绝对位置仍使用 1600×1000 的逻辑坐标；设备只改变
整个画布的一个缩放值。它不会像普通响应式网页一样换行、改列、挪动元素或改变
单个字号。剩余宽度或高度由 `.slide-letterbox` 的黑色背景填充，行为与 PPT
放映一致。

`SlideViewport` 同时暴露以下 DOM 诊断信息，便于回归测试：

- `data-slide-aspect="16:10"`
- `data-slide-logical-size="1600x1000"`
- `data-slide-scale="<当前缩放值>"`

## 数字人和教师指令

桌面端数字人位于右侧独立助手坞，教师可收起后扩大教学区域。窄于 980px 的设备
首次进入时默认收起数字人，保证教学内容优先；需要时仍可展开紧凑浮层。

手动收音遵循即时通讯应用的操作方式：

1. 仅在教师按住“按住说话”期间申请并采集麦克风。
2. 上滑超过 72px 标记为取消，松开后丢弃本次录音。
3. 正常松开后将录音、MIME 类型与时长发送到课次指令接口。
4. 单次录音最长 60 秒。
5. 可随时切换到文字输入，按 Enter 或发送按钮提交。

文字输入可在 LAM 离线时继续使用平台助手并显示字幕；语音按钮只在
OpenAvatarChat 会话真实连接后开放。录音在浏览器中解码、重采样为 16 kHz PCM，
经 `AvatarHandler.sendAudio` 进入 VAD 与百炼 ASR。最终 `EchoHumanText` 回到课堂
前端后，再进入与文字相同的平台编排链。

平台模型返回 JSON 流。浏览器通过 SSE 立即收到顶层 `dialogue` 的解码增量，并用
新增的 WebSocket `SendAvatarText` 通道送入 CosyVoice 和 LAM；OpenAvatarChat
的课堂配置中没有 LLM handler。完整 JSON 通过服务端严格校验
后，平台才执行翻页或活动切换，前端不再解析模型控制块。

课程上下文采用“航次档案 + 讲级知识包 + 当前页叙事上下文”：每次根据稳定
`slideKey` 注入当前位置、航次阶段、证据状态、未决问题、标题、正文、数据、
表格、问题和来源，页级内容不超过 700 字。模型优先依据当前页回答，再使用当前
讲知识包；未建设课次和未提供的事实必须明确说明，不能补写。原始
`teachingCue` 保留给教师，不直接进入模型。

当前 108 页课程以 OOCL Spain 2023 年 LL3 历史航次快照贯穿前三讲。页面把证据
明确分为“真实资料 / 教学情境 / 概念模型”；模型回答教学情境时必须明说
“在本教学情境中”，不能把假设货物、中断、绕航或诊断任务包装成真实事件。
学生可见的页顶信息只显示地点、时间和必要的“史料 / 官方资料 / 教学情境 /
路线示意”标签。航次阶段、故事节拍、未决问题、`teachingCue` 和
`assistantCue` 仍供课程引擎使用，但不渲染或附着在共享 Slide DOM。

底部课次控制是由课程目录驱动的 16 讲下拉菜单。第1—3讲分别从第 1、37、73 页
进入；第4—16讲以“待建设”禁用项出现。数字人可通过 `lesson.go_to` 使用同一份
课次目录跳转，因而不存在前端按钮与模型页码映射不一致的问题。

课件状态同时保存 `deckVersion` 和 `slideKey`。当前版本为
`release-port-management-voyage-v4`；版本变化时优先按有效 `slideKey` 保持原页，
只有键已失效或旧状态只有数字页码时，才回到旧页码所属讲的新版封面。

连接离线、预热、资源装载、ASR 等待、模型思考、对白流式生成、TTS 播放和会话
异常均显示真实状态，不用图片占位符冒充数字人，也不虚构 GPU 延迟。

课堂用 Barbara 的 LAM 实时渲染；课下轻量卡通/预录方案属于另一种使用场景，
不再作为课堂页中的“切换模式”按钮。

## 在线人数口径

在线人数不来自种子数据或界面常量。邀请按钮复制 `/join/:sessionId` 学生专用链接；
学生页面进入后每 15 秒发送课次心跳，平台按 `sessionId + participantId` 去重。
页面正常离开会尽力通过 `sendBeacon` 注销；断网、崩溃或浏览器未发送离开事件时，
最后一次心跳超过 45 秒仍会自动过期。因此尚无学生连接时，教师端明确显示
“暂无学生在线”，而不是用一个好看的预设人数。

当前 JSON 开发适配器把租约放在 API 进程内存中，API 重启会归零。生产阶段学生端
应使用鉴权后的用户/设备会话作为 `participantId`，并把同一租约语义迁移到 Redis，
从而支持多实例部署；在这之前不会把测试数据包装成真实在线人数。

## 课堂 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/avatar/runtime/status` | 探测 OpenAvatarChat 的存活、就绪、WS + LAM 配置、Barbara 资源和版本 |
| `GET` | `/api/class-sessions/:id/snapshot` | 读取课堂、Slide、活动和数字人完整快照 |
| `POST` | `/api/class-sessions/:id/presence/heartbeat` | 学生端续租在线状态，租约为 45 秒 |
| `POST` | `/api/class-sessions/:id/presence/leave` | 页面关闭时通过 `sendBeacon` 尽力提前注销租约 |
| `DELETE` | `/api/class-sessions/:id/presence/:participantId` | 学生端主动离开 |
| `POST` | `/api/class-sessions/:id/events` | 翻页、跳页、切换活动或切换数字人模式 |
| `POST` | `/api/class-sessions/:id/avatar/commands` | 提交文字或录音教师指令 |
| `POST` | `/api/class-sessions/:id/assistant/turns` | 以 SSE 返回对白增量，并在完整 JSON 校验后执行课堂动作 |
| `POST` | `/api/class-sessions/:id/end` | 保存课次并释放实时数字人状态 |

## 已验证的设备适配

下表来自 2026-07-30 对 108 页 v4 课件的真实浏览器验收。固定画布始终保持
`1600×1000 / 16:10`：

| 浏览器视口 | 可用画框 | 实际 Slide | 缩放 | 黑边方向 |
| --- | --- | --- | --- | --- |
| 1280×720 | 922×512 | 819×512 | 0.5120 | 左右 |
| 980×720 | 约954×512 | 819×512 | 0.5120 | 左右 |
| 680×720 | 约664×542 | 664×415 | 0.4150 | 上下 |

980 和 680 通过同源窄屏承载页形成真实子视口，媒体查询按子视口宽度生效；承载页
仅用于验收并已移除。680 宽度下数字人默认折叠为 62px 工具条并上移到控制栏之上，
不会遮住翻页、课次选择、指针、批注、互动或全屏按钮。活动标签栏隐藏滚动条且
没有纵向溢出。

v4 课件本轮实际结果：

- 浏览器通过正常“下一页”动作依次走完 108 页，得到 108 个唯一 `slideKey`：
  35 页真实资料、17 页教学情境、56 页概念模型。
- 26 个含图页面（24 幅素材中有少量跨页复用）全部加载成功；没有断图、正文裁切、
  文本越界、缺失来源页脚或缺失“教学复原图”标签。
- 学生可见的页顶只显示地点、时间和必要公开标签；108页共享DOM均没有
  `teachingCue`、`assistantCue`、故事节拍、“未决”文案或教师提示属性。
- 16 项课次菜单中前三讲可选，第4—16讲共 13 项禁用；实际选择第2、3讲分别跳到
  第37、73页，活动状态自动回到 Slides。
- 1280、980、680 三种视口均无页面横向溢出，逻辑画布尺寸与 `data-slide-aspect`
  始终为 `1600×1000 / 16:10`。
- 初始在线人数仍显示“暂无学生在线”，不使用装饰性人数；单元测试覆盖加入、离开
  和 45 秒租约过期。
- Barbara LAM 使用真实组件并显示实际连接状态；未用静态头像冒充在线渲染状态。

此前的 LAM 流式对白、ASR 和控制链路验收仍然有效：`dialogue` 可在完整 JSON
闭合前进入字幕和 TTS，动作只在完整 Schema 校验后执行；无效尾部不会执行控制。
